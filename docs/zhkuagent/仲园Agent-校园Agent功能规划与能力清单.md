## 0. 一句话结论

当前工程已经是一个**"可信知识治理 + 受限规则问答"的扎实底座**（工程严谨度明显高于同届简历），但它还**不是 Agent**：校园问答链路里没有大模型、没有工具调用、没有多步规划，回答来自确定性关键词路由。

因此，面向"Agent 方向实习"的最优策略不是推倒重来，而是**"补齐缺口 + 放大优势"**：

- **补齐缺口**：接入 LLM 编排（RAG 生成 + Function Calling 工具调用 + 混合检索 + 评测数字），把"问答"升级为"Agent"。
- **放大优势**：把已有的运行时生命周期、并发/取消/幂等、任务状态机、证据账本文化，包装成**面试可直接讲的工程故事**。

### 1.4 现状中的 5 个关键发现（需先处理）

1. **文档与代码已对齐（2026-09-20 修正）。** 根 `README.md` 与 `knowledge/README.md` 已说明两轮澄清能力；实现位于 `conversation/elective` 与 `conversation/publicelective`。后续对外叙述仍应以代码 + 证据账本为准，避免简历与仓库自相矛盾。
2. **阶段 7 未提交，基线不干净。** `notice/`、`V6`–`V8`、阶段 7 计划与证据账本均为未跟踪文件。**在叠新功能前必须先固化一次可复现的绿基线**，否则后续任何回归都无法归因。
3. **最大能力缺口：校园链路里没有 LLM。** 当前"回答"是关键词命中 + 模板拼接。面试官问一句"你的 Agent 在哪里？"就会露馅。这是本次规划要优先补的核心。
4. **稀缺优势已存在，但没被讲出来。** 并发安全运行生命周期、取消竞态、乐观并发、幂等清理、任务状态机、证据账本——这些是**同届简历几乎不会有的工程硬功**，应当作为差异化主线包装。
5. **历史包袱与可复用样板并存。** `agent/` 仍带 LoveApp/恋爱、image-search MCP、PGVector 原型。恋爱域应继续隔离；而 **MCP 工具工程、ToolCallAgent、PGVector 配置恰恰是"工具接入"的现成样板**，值得复用而不是删除。

### 1.5 成熟度定位

按项目自定的 RAG 分级：当前校园知识问答处于 **R0（基础设施存在）到 R1（链路接入）之间**——有 pgvector 扩展和确定性链路，但**未接模型、未写向量、未做语义检索**。阶段 7 完成后仍只是 R1 的前置条件。

**结论：现在正好处在"补最后一块拼图就能讲完整故事"的位置。**

## 2. 校园 Agent 的能力模型

### 2.1 与"校园问答机器人"的本质区别

| 维度 | 问答机器人 | 校园 Agent |
| --- | --- | --- |
| 输入 | 一个问题 | 一个目标（"帮我看下学期怎么选"） |
| 处理 | 检索 → 复述 | 规划 → 调工具 → 校验 → 分步交付 |
| 能力 | 知识问答 | 知识问答 **+ 计算/查询/规划工具** |
| 失败处理 | 拒答 | 降级、澄清、转人工渠道 |
| 可观测 | 看回答对不对 | 看路由、召回、引用、耗时、成本 |

**判断标准**：一个系统只要"能多次调用工具、并根据工具结果决定下一步"，就跨入了 Agent 范畴——哪怕工具全是只读的。

### 2.2 七层能力模型

1. **交互与对话层**：多轮会话、意图识别、槽位填充、流式输出、答案卡。
2. **知识治理层**：资料入库、审核发布、版本替代、时态生命周期、多资料域。
3. **检索引擎层**：切分与索引版本、词法检索、向量检索、混合融合、重排。
4. **生成与约束层**：受控 RAG 生成、引用白名单、注入防护、拒答与降级。
5. **工具与行动层**：只读校务工具、计算工具、办事清单、人工转介。**← Agent 的核心分水岭**
6. **评测与观测层**：版本化评测集、检索/生成指标、无文本观测、隐私与留存。
7. **工程基座层**：迁移纪律、环境隔离、一键验收、可恢复任务、并发与幂等。

## 4. 按优先级排列的功能规划

### 4.1 优先级判据

- **简历竞争力**：对"Agent 方向实习"的**区分度**（面试官是否愿意追问）。
- **交付速度**：**复用现有资产**的程度（越小越快）。
- **依赖前置**：是否被其他项阻塞。

标记约定：**🏆 = 简历王牌**（最该讲）；**⚡ = 快赢**（复用骨架、快速见效）。

工作量：**S** = 复用现有骨架、改动集中；**M** = 需新增模块/迁移/测试；**L** = 跨模块、需新基建。

---

### 4.2 P0：立刻做（决定项目能否被称作"Agent"）

| # | 功能 | 层 | 标记 | 现状 | 工作量 | 简历价值 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **受控 RAG 生成层**（模型只在白名单证据内表达，输出结论/不确定度/引用 ID/是否转人工） | 生成 | 🏆 | 无模型 | M | 极高：这是"Agent 回答"的证据 |
| 2 | **校园工具集 + Function Calling**（学分计算、选课冲突检测、毕业学分进度、校历/课表查询；全部只读或纯计算） | 工具 | 🏆 | 无 | M | 极高：Agent 的核心分水岭 |
| 3 | **统一路由编排器**（待澄清 → 当期通知 → 高风险规则 → 检索增强 → 拒答/人工） | 交互+生成 | ⚡🏆 | 有 Router 雏形 | S | 高：可讲"编排优先级矩阵" |
| 4 | **向量检索 + 混合融合（RRF）** | 检索 | 🏆 | 仅设计 | L | 极高：RAG 硬指标来源 |
| 5 | **引用白名单校验 + 注入防护 + 降级** | 生成 | ⚡🏆 | 仅结构约束 | S | 极高：可信 AI 的差异化 |

**为什么这五项是 P0：** 1、2 让项目从"问答机器人"变成"Agent"；3 把它组织成可讲的一条链路；4 提供可量化的检索数字；5 把项目最擅长的"严谨"变成安全故事。缺 1 或 2，简历的 "Agent" 标题就站不住。

**关键设计要点（不含实现）：**
- 模型输出必须是**受限结构**（结论 + 不确定度 + 引用 ID + 是否转人工），服务端丢弃非白名单引用与越界结论——延续项目"数据结构级防线"的既有风格。
- 工具**只读或纯计算**，绝不代办、不写校务系统——这样既保住安全边界，又能拿到"工具调用"这个简历要点。
- 混合检索**保留单路降级并记录原因**，不把"一路可用"冒充"混合检索"——这本身就是面试可讲的严谨点。

### 4.5 最小可交付纵切（MVP：最快形成"可演示 + 可写简历"的闭环）

如果目标是**尽快交付**，建议只做这 5 项就收口，其余全部后移：

```
① 统一路由编排器（复用现有 Router 雏形）        → ⚡ S
② 校园工具集：学分计算 + 选课冲突检测（2 个即可） → 🏆 M
③ 受控 RAG 生成（模型 + 引用白名单 + 拒答）      → 🏆 M
④ 最小版本化 Eval（20~30 题 + 4 个指标）        → 🏆 M
⑤ 校园问答流式返回 + 答案卡升级                  → ⚡ S
```

这一纵切交付后，你可以诚实地说：**"我实现了一个校园 Agent：能在可信知识上做工具调用（学分计算/选课冲突），用受控 RAG 生成带引用白名单的回答，无有效证据时降级为澄清或人工渠道，并在版本化评测集上给出检索与拒答指标。"** —— 这句话对 Agent 方向实习的杀伤力，远大于"我做了个校园问答系统"。

### 4.6 不建议现在做（保住边界）

- ❌ 自动化爬取校网通知（项目已明确不自动抓取，人工审核是可信前提）。
- ❌ 接入真实学籍/成绩/审批/校务写操作（安全边界，也是项目的诚信底线）。
- ❌ 强行扩充"校园万能助手"叙事（项目文档已划出诚实边界，过度包装反而在面试中被拆穿）。
- ❌ 为凑功能而做重排/多模型路由（**没有评测数据前不要开**，否则无法回答"效果如何"）。

## 6. 简历与面试表述边界

沿用项目既有的诚实规范，落到"现在 / 做完 MVP 后"两档：

| 现在就能写 | 完成 MVP（4.5）后才能写 | 仍不能写 |
| --- | --- | --- |
| 可信知识治理：审核发布 + 版本替代 + 学生可见过滤 | 校园 Agent：工具调用 + 受控 RAG 生成 | 生产上线 / 服务全校学生 |
| 会话工程：不可变状态 + 乐观并发 + 取消竞态 + `Clock` 过期 | 混合检索 Recall@K / MRR 等**带分母**指标 | 自动抓取校网通知 |
| 动态通知：学期/时态/替代治理 + 到期强制拒答 | 引用白名单校验 + 注入防护 + 降级 | 校园 RAG 已上线 / 效果提升 X% |
| 运行时工程：独立运行上下文 + 停止/清理分离 + cleanup 幂等 | 可恢复长任务（若做 P1 #9） | 高并发 / 生产 SLA |
| `knowledge` 模块 155 项自动化测试通过 | — | 真实学生使用数据 |

**三条最适合包装成面试故事的证据链**（项目文档已梳理，建议直接复用）：
1. **新版替代避免旧证据误答**：事务替代 → 只看到当前有效版本 → 发布失败回归测试 → 引用到版本与页码。
2. **取消与乐观并发控制**：不可变状态 + 版本号 → 晚到写入判为陈旧 → 取消后不可复活 → 前后端竞态测试。
3. **时态过滤 + 受控检索 + 引用校验**（P0 完成后可用）：通知有效性过滤 → 词法/向量融合 → 模型只能输出白名单引用 → 无证据拒答 → 版本化评测结果。
