# 仲园 Agent：可信知识与 Agent 工程证据规范

> 版本：`0.1`  
> 记录日期：2026-09-16  
> 适用范围：仲园 Agent 阶段 7—10，以及后续新增的规则、资料、检索、模型调用和隐私能力。

## 1. 目的与诚实边界

本规范解决两个问题：一是让每项学生可见能力都能追溯到代码、测试和资料证据；二是避免把“讨论过”“依赖已引入”误写成“已经上线”。它不替代代码评审、数据审核或人工验收。

当前可以如实陈述的基础是：

| 技术点 | 当前状态 | 已有事实 | 不能得出的结论 |
| --- | --- | --- | --- |
| 审核发布与学生可见过滤 | 已实现并已验收 | `knowledge_source` 的发布、可见范围、分享权利字段；学生检索过滤；范围替代发布事务 | 尚无动态通知有效期和网页快照治理 |
| 会话状态与并发保护 | 已实现并已验收 | 不可变状态、`revision + expectedRevision`、`Clock`、取消竞态测试 | 不代表分布式存储或高并发压测已经完成 |
| 首批制度/公共选修规则问答 | 已实现并已验收 | 受限路由、回答卡、来源定位、页面闭环 | 不代表已经覆盖全校制度或当期通知 |
| pgvector/SSE 基础设施 | 基础设施存在 | `agent` 模块保留 Spring AI、pgvector 和 SSE 相关原型 | **不是校园 RAG 链路，未接入知识模块，不得写“校园 RAG 已上线”** |
| 阶段 7—10 能力 | 仅设计/计划中 | 本文及配套实施计划 | 不得在简历或演示中表述为已实现 |

以下表述在阶段 8 真实接入、完成评测前禁止使用：`搭建校园 RAG 知识库`、`已支持多模型问答`、`混合检索提升召回率`、`生产可用`。更准确的当前表述是“完成可追溯知识治理与受限规则问答基础，正在按计划建设时态知识和检索增强链路”。

## 2. 不可突破的产品边界

1. 学生可见结论必须先通过：发布状态、学生可见/分享权利、版本替代、动态时效、适用范围五项检查；任一项不满足，返回证据不足或官方人工渠道。
2. 模型只能基于当轮已获准的证据组织表达，不能认定资格、成绩、审批结果、课程是否开设，也不能承诺办理成功。
3. 会话记忆只用于补全当前澄清项，永远不是制度依据；用户输入和资料文本都是不可信数据，不能改变系统指令或工具权限。
4. 不调用校务系统、不代表学生提交申请、不收集学号、姓名、联系方式或自由文本反馈。
5. 密钥只能由环境变量或本地密钥管理注入；日志、异常、接口、截图和 Git 均不得出现密钥。
6. 数据库迁移只能追加新的 Flyway 版本；不得修改既有 `V1`—`V5` 历史。

## 3. 开发时必须保留的面试证据记录

每个涉及规则、知识、检索、模型调用、会话或隐私的新能力，在实现 PR/提交同批新增一条记录。记录可写在 `docs/evidence/`，命名为 `YYYY-MM-DD-能力名-证据账本.md`。没有数据的字段必须写“待评测”，不能补造数字。

```text
技术点：
当前状态：已实现 / 仅设计 / 计划中
解决的问题：
个人负责范围：
核心设计与取舍：
为什么不采用其他方案：
关键业务边界或安全约束：
代码位置：
自动化测试位置与覆盖场景：
可量化指标、基线与统计口径：
失败案例、已知限制或降级方案：
简历可使用的诚实表述：
面试可能追问及回答事实：
```

“已实现”最低证据门槛是：生产代码、一个正常用例自动化测试、一个边界或失败用例自动化测试，以及本地运行结果。需要人工操作的流程，还要增加人工验收记录。没有这些材料，只能标注“仅设计”或“计划中”。

## 4. 需要特别留证的工程要点

| 主题 | 必须留存的设计/测试证据 | 常见错误与防线 |
| --- | --- | --- |
| 知识版本与替代 | 资料族、范围、版本、替代关系、原子发布测试 | 只靠发布时间排序会让旧通知与新通知同时作答 |
| 动态通知 | 学期、通知类型、开始/结束、官方 URL、快照哈希、抓取时间、审核人、时钟边界测试 | 缺少确认学期或任一时段时，不能输出具体日期或资格 |
| 会话与并发 | 状态图、`revision` 语义、取消—旧写回竞争测试、前端请求序号/中止证据 | 取消后晚到响应污染新会话 |
| 规则路由 | 路由优先级矩阵与每条优先级测试 | 先调用模型再补规则，会放大错误资格判断 |
| 检索 | Chunk 样例、检索过滤条件、embedding/index/profile 版本、召回评测集 | 仅“有向量库”不等于有可用 RAG |
| 引用校验 | 当轮允许的 citation ID 白名单、模型伪造引用测试 | 让模型自行编造页码或链接 |
| Prompt 注入 | 把文档/用户文本标为不可信证据、注入测试集 | 把资料中的“忽略指令”当作系统命令 |
| 模型提供商 | Base URL、模型名、兼容协议版本、超时/限流/失败降级的合同测试 | 用一个供应商成功就宣称所有兼容 API 都可用 |
| 反馈和隐私 | 字段白名单、匿名会话散列、保留/删除任务、脱敏测试 | 保存原问题、回答、姓名或自由文本再声称匿名 |
| 指标 | 数据集版本、分母、基线、时间窗、环境、成功/失败计数 | 没有基线却写“准确率提升”或“显著降低” |

关键代码附近要补简明中文注释，说明为什么需要状态不变量、权限过滤、版本替代、时效判断、并发控制、拒答条件、密钥/隐私边界；不要复述语句本身。

## 5. RAG 成熟度分级

| 等级 | 可使用的表述 | 最低证据 |
| --- | --- | --- |
| R0：基础设施存在 | “具备 pgvector/SSE 原型基础” | 依赖、配置或隔离原型；不等于问答链路 |
| R1：链路接入 | “已接入受控检索增强链路” | 发布资料切分、索引、检索前过滤、引用白名单、正常/拒答测试 |
| R2：完成评测 | “在版本化评测集上完成检索与引用评测” | 数据集、分母、Recall@K/MRR 等结果、失败样例、运行环境 |
| R3：受控试运行 | “在本地受控演示环境可用” | 发布质量门禁、降级、审计、隐私验证与人工验收 |

除非获得真实生产环境授权、访问控制、运维监控和持续运行证据，不得使用“生产上线”“服务全校学生”。

## 6. 指标记录规范

每个指标至少同时记录：数据集版本、题目总数（分母）、统计时间范围、代码/索引/模型版本、运行环境、失败与跳过数量。

- 检索：`Recall@K`、`MRR`、`nDCG`。仅对有明确黄金证据的题目计入分母。
- 生成：忠实性、引用准确率、拒答准确率。关键安全题不以平均值掩盖失败，必须逐题通过。
- 运行：端到端延迟（p50/p95）、模型失败率、降级次数、估算 token 成本；没有稳定采样不能承诺性能。
- 版本：每次嵌入模型、向量维度、索引策略或 Prompt 改动，生成新 profile/version；更换 embedding 必须新建索引、回归评测、原子切换、保留旧索引直到回滚窗口结束。

## 7. 最适合沉淀为面试故事的三条证据链

1. **新版替代避免旧证据误答**：新旧同范围资料的事务替代 → 学生检索只看到当前有效版本 → 旧版本/发布失败回归测试 → 回答引用到版本和页码。
2. **取消与乐观并发控制**：不可变状态 + 版本号 → 晚到写入返回陈旧写入 → 取消后不可复活 → 前后端竞态测试。
3. **时态过滤、受控检索和引用校验**（阶段 8 完成后才可使用）：通知有效性过滤 → 词法/向量候选融合 → 模型只能输出白名单引用 → 无有效证据拒答 → 版本化评测结果。

这些故事都应按“问题—个人动作—取舍—可核验结果—边界/失败案例”陈述，而不是只说“做了 Agent/RAG”。
