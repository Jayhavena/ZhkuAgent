# 仲园 Agent 匿名反馈管理员操作手册

> 适用范围：阶段 9 的匿名枚举反馈闭环。本手册只描述本机预览环境中的反馈接收、聚合查看与保留处理；管理员界面由 WB-1 另行交付。

## 1. 反馈接收边界

学生侧通过 `POST /zhku/feedback` 提交反馈。请求只能包含清单标识 `guideIdentifier`、清单版本 `guideVersion`、原因 `reason` 和 64 位十六进制匿名会话散列 `anonymousSessionHash`。

系统只接收以下四种原因：

| 枚举 | 含义 |
| --- | --- |
| `NOT_HELPFUL` | 清单未能帮助完成当前办事步骤。 |
| `INCORRECT` | 清单中的说明与实际办理情况不一致。 |
| `OUTDATED` | 清单可能已过期，需要管理员复核版本或时效。 |
| `MISSING_INFORMATION` | 清单缺少完成该事项所需的关键信息。 |

未知字段、自由文本、学生身份或联系方式都会返回 `400`，不会被静默保存。尤其不得把原问题、原回答、姓名、学号、联系方式或工单说明填入该接口。

首次提交返回 `201`；同一 UTC 自然日内、同一匿名散列、同一清单标识/版本和同一原因的重复提交返回 `200`。两种回执只说明是否接收及是否重复，绝不会返回匿名散列、去重键或事件 ID。

## 2. 90 天保留与聚合

系统只保留匿名散列、去重信息、受限原因枚举和处理所需时间字段。到创建时刻满 90 天后，管理员显式执行保留处理：系统按清单标识、版本、原因和创建日期累加为汇总数据，再删除到期的逐条事件。

保留处理不会改变仍在 90 天内的事件。管理员看到的是统计结果，不是单条反馈或可反推个人的明细。

## 3. 管理员操作

1. 通过 `GET /zhku/local-admin/feedback/aggregates` 查看聚合结果。每项只包含 `guideIdentifier`、`guideVersion`、`reason`、ISO 日期 `feedbackDate` 和正整数 `count`。
2. 在确认需要清理到期事件时，显式调用 `POST /zhku/local-admin/feedback/retention`。响应仅返回已聚合处理的事件计数 `aggregatedEventCount`。
3. 将异常趋势与对应清单版本交由内容管理员人工研判；聚合数字本身不构成制度结论或自动修改依据。

管理员读取接口始终只返回聚合数据。若需要调整清单，应走既有人工审核与发布流程，而不是从反馈接口直接写入资料。

## 4. 产品承诺与禁止事项

- 反馈不会自动创建资料候选、不会发布资料、不会建立索引任务。
- 反馈不会自动调整检索排序、提示词或制度结论。
- 系统不接入工单、短信、邮箱、校务系统或学生身份服务。
- 如需联系学生或收集详细说明，必须使用经单独审批的渠道；不得绕过匿名反馈接口扩展字段。
