# 仲园 Agent 极简本机问答页面设计

## 1. 文档目的

本文定义“仲园 Agent”的首个面向普通用户的本机问答页面。它只为当前已实现的校园知识问答闭环提供一个可操作、可观察的界面，不新增知识入库、模型调用、登录、上传或历史记录能力。

页面服务于本机验证：开发者启动专用应用后，可在浏览器中提问，并直接看到回答、资料出处或“资料不足”的明确提示。

## 2. 背景与问题

当前系统已经具备本机 HTTP 问答接口：

- 已审核的公共选修课程知识片段已写入本机 PostgreSQL；
- 对已覆盖问题，接口返回带出处的 `GROUNDED` 回答；
- 对资料未覆盖的问题，接口返回 `INSUFFICIENT_EVIDENCE`，且不伪造出处；
- 接口仅监听 `127.0.0.1`，并通过 `zhku-local-preview` 专用启动入口隔离于通用 Agent 应用。

现有验证方式依赖 PowerShell 调用接口。它能证明后端正确，但学生或非后端开发者难以直观理解“提问—回答—出处—资料不足”的产品闭环。页面的目标是让这条链路可直接体验，而不是提前建设完整聊天产品。

## 3. 范围

### 3.1 本次包含

1. 本机浏览器页面，页面名称为“仲园 Agent｜校园资料问答”。
2. 一个问题输入框和“查询资料”按钮。
3. 调用现有 `POST /api/zhku/local-preview/answers` 接口。
4. 展示三类主要结果：有依据回答、资料不足、服务或输入错误。
5. 在有依据回答下紧贴展示来源标题、定位信息和页码。
6. 明确标注“本机验证”和资料覆盖范围限制。

### 3.2 本次不包含

- 用户登录、身份认证、成绩、学籍、身份证件或其他敏感校务数据；
- 用户上传、人工审核、资料发布后台；
- 大模型生成、语义检索、向量检索、联网搜索；
- 对话历史、收藏、点赞、问题分析或持久化；
- 公开部署、外网访问和多租户权限；
- 移动端原生应用。

## 4. 设计原则

1. **依据优先**：答案不是结论的终点，出处必须紧贴答案出现。
2. **资料不足优先于猜测**：未覆盖问题必须明确说明当前不能确认，而不是给出看似合理的校园规则。
3. **本机隔离**：页面只能随本机预览专用应用暴露，不能被通用 Agent 启动入口意外公开。
4. **最小实现**：采用单页静态 HTML、CSS 和原生浏览器 JavaScript，不引入独立前端工程、构建工具或第三方界面框架。
5. **可读性优先**：采用单栏阅读流，适合中文回答与资料定位信息，不模拟即时聊天软件。

## 5. 用户与核心旅程

目标用户是参与本机验证的开发者、产品同学和少量受邀学生。第一批资料范围仅为已审核的公共选修课程规则。

### 5.1 有依据回答

1. 用户通过浏览器打开本机页面。
2. 页面说明仅基于已审核资料回答，用户输入“公共选修课每学期最多修多少学分？”。
3. 用户点击“查询资料”或在输入框中按回车。
4. 页面显示“已找到资料依据”、回答正文和来源卡片。
5. 用户能看到来源为《本科生学生手册（2025版）》及对应 PDF 页码、条款定位。

### 5.2 当前资料未覆盖

1. 用户输入“奖学金申请截止日期是什么时候？”。
2. 接口返回 `INSUFFICIENT_EVIDENCE`。
3. 页面显示“当前资料未覆盖该问题”，并解释不提供未经资料支持的答案。
4. 页面不展示空白出处区域，也不展示虚构来源。

### 5.3 异常与修正

1. 用户提交空问题或超过 500 个字符的问题。
2. 页面保留输入内容，在输入区域附近提示“请输入 1 至 500 个字符的问题”。
3. 若本机数据库不可用或服务未启动，页面显示“本机知识服务暂不可用，请确认预览服务和数据库均已启动”，不展示密码、连接串或内部异常详情。

## 6. 页面结构与视觉规范

采用用户已确认的方案 A：**资料依据紧贴回答**。

```text
┌────────────────────────────────────────────┐
│ 仲园 Agent                         本机验证 │
│ 校园资料问答                               │
│ 仅基于已审核资料回答；资料不足会明确说明。 │
│                                            │
│ [ 请输入校园问题                         ] │
│                              [查询资料]    │
│                                            │
│ ┌─ 回答区 ───────────────────────────────┐ │
│ │ 已找到资料依据                         │ │
│ │ 回答正文……                             │ │
│ │ ┌─ 资料依据 ─────────────────────────┐ │ │
│ │ │ 本科生学生手册（2025版）             │ │ │
│ │ │ PDF 第 76—77 页，第 8、10 条         │ │ │
│ │ └────────────────────────────────────┘ │ │
│ │ 仅供本机验证；请以学校正式通知为准。   │ │
│ └────────────────────────────────────────┘ │
└────────────────────────────────────────────┘
```

视觉语言使用“校园资料册”而非聊天软件风格：深农业绿用于标题和操作按钮，米纸色背景承载阅读，暖棕色用于出处标记。建议色值如下：

| 用途 | 色值 |
| --- | --- |
| 主色（深农业绿） | `#17382D` |
| 强调色（叶绿） | `#317047` |
| 页面背景（米纸） | `#F7F5ED` |
| 卡片背景 | `#FFFEF9` |
| 分隔线 | `#D2DCCD` |
| 出处强调（暖棕） | `#AD6A35` |

页面在窄屏下保持单栏，输入框与按钮可上下排列；不以像素级响应式适配作为本次验收范围。

## 7. 页面状态与交互约定

| 状态 | 触发条件 | 页面行为 |
| --- | --- | --- |
| 初始 | 首次打开 | 展示说明、输入框和示例问题；不展示旧回答。 |
| 查询中 | 已提交且请求未返回 | 禁用按钮，按钮文字变为“正在查询资料…”。 |
| 有依据回答 | `mode=GROUNDED` | 显示回答、至少一条出处和接口返回的提示信息。 |
| 资料不足 | `mode=INSUFFICIENT_EVIDENCE` | 显示资料不足说明；隐藏整个出处区。 |
| 输入错误 | HTTP 400 或浏览器端校验失败 | 在输入框附近提示用户修正问题，不清空原输入。 |
| 服务不可用 | HTTP 503、网络失败或非预期响应 | 显示本机服务不可用提示；不泄露后端细节。 |

提交时应先在浏览器端去除首尾空白并检查长度。回答和出处字段必须通过安全的文本节点写入页面，不能把接口返回内容当作 HTML 直接插入。

## 8. 技术边界与组件关系

### 8.1 推荐实现方式

在现有 `zhku-local-preview` 隔离条件下新增一个页面控制器：

- `GET /api/zhku/local-preview`：返回页面资源；
- `POST /api/zhku/local-preview/answers`：继续使用既有问答接口；
- `src/main/resources/zhku/local-preview/index.html`：单文件页面资源，包含样式与脚本。

页面控制器与现有问答控制器使用相同的 `zhku-local-preview` Profile 和 `zhku.local-preview.enabled=true` 条件。资源不放到通用静态目录中，避免普通应用入口无意暴露页面。

```text
浏览器
  │ GET /api/zhku/local-preview
  ▼
本机页面控制器（仅预览入口启用）
  │ 返回 index.html
  ▼
页面脚本
  │ POST /api/zhku/local-preview/answers
  ▼
既有本机问答控制器
  ▼
GroundedAnswerService
  ▼
已发布知识片段 / 本机 PostgreSQL
```

### 8.2 不新增的后端业务逻辑

页面不解释规则、不判断资料覆盖范围、不组装出处。上述工作继续由既有服务完成。页面只将问题发送给接口，并根据已定义的响应字段渲染状态，避免浏览器与后端出现两套问答规则。

## 9. 接口契约

页面依赖现有响应字段，不改动接口地址和含义：

```json
{
  "mode": "GROUNDED",
  "answer": "学生应以人才培养方案为选课依据……",
  "citations": [
    {
      "sourceTitle": "本科生学生手册（2025版）",
      "sourceLocator": "PDF 第 76—77 页，第 8、10 条",
      "pageNumber": 76
    }
  ],
  "notice": "仅供本机验证；请以学校正式通知为准。"
}
```

约定如下：

- `GROUNDED` 必须有非空 `answer`，且本次数据集下至少有一条 `citations`；
- `INSUFFICIENT_EVIDENCE` 不展示 `citations`；
- `notice` 原样作为提示信息展示；
- 任何不符合上述约定的响应视为服务异常，而非作为正常答案渲染。

## 10. 验收标准

### 10.1 自动化验证

1. 预览专用启动入口启用时，`GET /api/zhku/local-preview` 返回 UTF-8 HTML 页面。
2. 预览条件未启用时，页面路由不可用，确保没有意外暴露给通用应用。
3. 页面资源包含对既有问答接口的唯一调用地址。
4. 已有问答接口的 200、400、503 行为继续由现有控制器测试覆盖。

### 10.2 手工验收

1. 在本机启动预览应用后，浏览器访问 `http://127.0.0.1:8123/api/zhku/local-preview` 能打开页面。
2. 输入公共选修课问题，页面显示中文正常、回答完整、出处紧贴回答。
3. 输入奖学金截止日期问题，页面明确显示资料不足，且无出处卡片。
4. 提交空问题、过长问题、停止数据库或服务后，页面能给出对应提示且不泄露技术细节。
5. 页面不出现登录、上传、历史记录、模型名称或敏感数据输入入口。

## 11. 风险与约束

| 风险或约束 | 当前处理 |
| --- | --- |
| 资料范围窄，容易被误认为校园全知识库 | 页面首屏和资料不足状态都说明当前仅基于已审核资料。 |
| 页面让用户误以为结论具有校务权威性 | 始终展示“请以学校正式通知为准”。 |
| 预览页面被普通应用暴露 | 使用专用 Profile、显式开关和非通用静态资源路径。 |
| 浏览器渲染接口内容带来脚本注入风险 | 使用文本节点渲染，不使用 `innerHTML`。 |
| 提前引入前端工程导致维护成本上升 | 第一版保持单文件页面，等待真实交互复杂度出现后再评估拆分。 |

## 12. 完成定义

当页面在本机预览应用中可用，且用户能独立完成“有依据回答”和“资料不足”两种旅程，并通过自动化与手工验收标准时，本页面功能完成。完成不代表已经具备公开发布条件，也不代表已经引入 RAG 或多步骤 Agent 能力。
