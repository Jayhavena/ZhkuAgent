# JDBC 会话持久化证据账本

> 状态：**已实现，待合并**。本记录只覆盖线 B 首个独立交付：PostgreSQL 会话存储、V12 迁移、契约测试与本机 PostgreSQL 预检脚本；运行时 Bean 切换、SSE、工具调用与前端体验不在本次范围内。

## 交付范围与设计边界

| 字段 | 记录 |
| --- | --- |
| 解决的问题 | 现有 `InMemoryConversationStore` 随进程重启丢失状态，且无法在多个实例间共享会话；本次提供与既有契约等价的 PostgreSQL 实现。 |
| 实现 | `JdbcConversationStore` 以 `conversation_session` 保存会话 ID、状态、待补充意图/字段、过期时间和修订号；`ConversationStoreFactory` 识别 `jdbc`，未配置仍返回内存实现。 |
| 并发取舍 | 写操作以“活动状态 + 未过期 + 当前 revision”为条件更新，并通过 `RETURNING` 判断是否成功。这样过期或已取消会话不会被滞后请求重新激活。 |
| 数据库迁移 | `V12__create_conversation_session_store.sql` 只追加新表和过期索引；状态、修订号与待补充字段组合均由数据库约束保护。未改写 V1–V8。 |
| 显式开关 | 保留冻结契约中的 `zhku.conversation.store=jdbc` 选择语义，但本次**不**修改 `ZhkuLocalPreviewConfiguration`，所以现有运行时仍使用内存实现。配置接线必须另行登记高冲突文件后再做。 |
| 环境启动 | `knowledge/scripts/ensure-zhku-postgres.ps1` 只检查 Docker、既有指定容器、健康状态和端口；容器已停止时仅执行 `docker start`。它不读取 `.env`、不执行 Compose、不创建容器或数据卷。 |

## TDD 证据

1. 先运行 `ConversationSessionSchemaTest`：迁移未存在时断言 `conversation_session` 缺失，得到预期失败；追加 V12 后通过。

3. 先加入工厂测试：`ConversationStoreFactory` 尚不存在时失败；实现“空值/空白为内存、精确 `jdbc` 为 JDBC、未知值拒绝”后通过。
