## 二、方案选择与官方依据（第一步）

- 结论：对固定模型 `qwen-plus`，北京 DashScope OpenAI 兼容接口**承诺工具调用、未承诺 JSON Schema 严格结构化输出**
  （该模式官方只列 Qwen3.7-Plus / 3.7-Flash / 3.8-Flash / 3.7-Max / 3.8-Max）。
- 关键限制：JSON Schema 数组 `uniqueItems` 提交即 400；工具 `parameters` 无 `strict` 语义；
  `tool_choice=required` 对 Qwen 系列不支持；官方建议开启结构化输出时不要设 `max_tokens`。
- 官方来源：`help.aliyun.com/zh/model-studio/qwen-structured-output`、`.../qwen-function-calling`、`.../qwen-api-via-dashscope`。
- 证据：`t05-23/README.md`、`t05-23/provider-capability-matrix.json`。
- 后续用户决策：改用支持 JSON Schema 严格模式的模型，并指定 **`qwen3.8-flash`**。

## 六、唯一剩余缺口

**模型未能在固定调用次数内恰好收敛到 FINISH。**

- 机制：每 run 4 次调用 = **3 次决策 + 1 次独立核验**；最小可用流程恰为 `SEARCH + READ + FINISH + REVIEW`。
  → **该形状对额外动作零容忍**：模型多走一步（重复 READ、重新 SEARCH），FINISH 即无席位，必然 `BUDGET_EXCEEDED`。
- 两批合起来证明：**检索、读取、候选编号映射、事实适用范围、宿主守卫与发布链路均已真机可用**；
  剩下的是模型选择行为与调用次数预算的耦合，**不是代码缺陷**。
- 不得用以下方式"消除"该缺口：放宽 1—3 句柄上限、自动截取前三个、默认选 `c1`、固定问题答案或白名单、
  跳过/弱化独立核验、静默回退旧协议或回放、换供应商。
