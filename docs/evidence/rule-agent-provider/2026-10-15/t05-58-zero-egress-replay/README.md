## 因果判断

两个独立拒绝边界已由冻结代码实测：首次是COMBINED事实未登记能力；移除这一触发后，原核验的带规则前缀条件ID确实导致CONDITION_NOT_NECESSARY。原核验的JSON和输入关联可以通过，条件ID“符合通用标识符形状”不等于“属于当前审核条件”。原模型为何选择COMBINED/为何加前缀仍未知，但已不是定位宿主拒绝分支的阻碍。

本地正例此前直接选已登记RETAKE_ONLY，缺少“真实READ返回混合事实集合→模型可选择项→前置检查→核验→Gate”的组合验收。当前可读事实集合和允许发布提议集合不是同一集合，代码没有把区别明确、统一地传给决策层并前置检查。

## 最小修正决策（尚未实施）

只修这条合同衔接，不扩大能力授权、不改原文和适用范围、不重构任务/发布系统：

1. 以现有能力目录及实际已读Fact指纹作为事实能力资格的统一来源，派生可用于ASK/FINISH的factId集合。保留全部已读事实、原文、候选和条件分支，同时向决策明确可发布支持ID及每条事实的资格。决策Schema/宿主前置检查/独立Gate引用同一资格规则；模型选择与原文保持可追溯。未登记或指纹不符的提议在独立核验前留下明确分支码并拒绝，消耗已发生的决策次数，但独立核验调用数必须0。合法完整提议仍执行独立核验及fresh发布检查。
2. 独立核验解码按本次SemanticInput.conditions验证necessaryConditionIds只能引用原键，并给出独立分支码（建议REVIEW_CONDITION_UNKNOWN）。现有跨度、事实/需求关联、能力、when、完整分支和发布守卫保留。带前缀或未知ID不得静默去前缀、自动补齐或替换成预设答案。该核验响应已经外发并产生usage，不能把拒绝当作未消费，也不增加重试额度。
3. 把本批完整事实集合固定为回归输入：覆盖COMBINED提议在核验前被明确拒绝、RETAKE_ONLY合法双分支可执行、前缀/未知条件键拒绝、缺一侧/身份漂移/非法动作不执行。另保留一个经真实EvidenceTools READ的集成用例核对资格集合生成，不能只手填“正确ID”作为全链验收。新出站字段和合同变更必须重新构建、绑定资产、披露并申请新包授权，不能沿用本批额度。

自动把COMBINED替换为RETAKE_ONLY会掩盖实际选择与身份差异；直接给COMBINED扩登记需要额外事实能力审核。两者都超出这次最低风险修正边界。前置拒绝会明确且节省无效核验，但仍可能消耗决策预算，不能承诺模型下一次一定改正或P02必过。

本决策的完成标准是“可执行范围一致、合法动作可执行、非法动作不执行且分支明确”，不是提高本地测试数量。真正P02仍须未来新授权下同task完成追问、续答、核验和发布；可靠性与产品质量另行评估。本轮到此停止，不实施修正、不生成新外发包、不申请或使用额度。
