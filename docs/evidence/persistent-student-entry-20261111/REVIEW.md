# 独立复核及主 Agent 处置

审查基准：`d9c64ac7b9ee598a0c8e7d8bd0f91f272c1c6433`，基线 main `04d17902`。OpenCode 请求模型 `opencode-go/deepseek-v4.1-flash`；编排器 executedModel 未提供，不据此证明供应商侧实际模型身份。子 Agent 只读静态审查并引用本机验收回执，没有重跑测试、启动服务、连接数据库或模型，也不是人类审批。

结论：限定本地零模型 GO，真实模型/在线 NO_GO。主 Agent 自行处理以下修正，无额外委派或声称再次获得独立签核。

| 发现 | 处置 |
| --- | --- |
| 页内登录后不刷新运行模式 | 登录及重新核对身份均加载模式；epoch 改变清旧模式，迟到响应不得覆盖新账号。以最终构建实测同一 `/rules` 组件内退出/登录、不刷新即显示模拟范围。 |
| 直接 Java ONLINE 的旧回放环境漏检 | 将三个实际存在的旧回放键传给同一供应商守卫，在 Options 阶段拒绝；单测逐键证明不进入 Spring/数据库/监听。 |
| 用量日志缺少任务关联 | 追加 taskId/runId 白名单 UUID；仍只称用量日志，不称持久审计已验收。真实模型、费用与真实用量日志未验证。 |
| 非唯一 TaskStore 会跳过退出检查；超时路径无覆盖 | 持久入口缺仓储/多仓储明确失败；新增超时错误与上下文关闭测试。保留 25 秒有界等待，文档明确超时失败及排队任务丢弃，不承诺跨重启任务终态保存。 |
| runtime 的 null 字段耦合及错误被吞 | ONLINE 允许省略 null 字段并正规化；模式读取失败给出可见的“暂无法确认”状态，不推断在线。前端校验新增先失败后通过的覆盖。 |
| 扫描测试名称不准确 | 测试重命名为条件守卫测试，不宣称真实整包扫描覆盖。旧应用误配模式导致启动失败的边界仍存在，不是自动启用在线能力。 |
| Restart 默认 SIMULATED | 手册明确不继承 ONLINE；继续在线须显式模式和本批外发授权。 |
| 证据未提交、浏览器来自较早构建 | 将脱敏 HTTP/关停/构建回执入库；修正后最终构建重新验页内登录和模式披露。早期失败及证据限制保留，不把旧构建冒充最终构建。 |

保留限制：未做 24 小时稳定性测试、未注入真实顽固线程、没有持久供应商费用账本、没有真实模型质量/账单验证。默认模拟只支持固定问题。学生原文与资格校验使用既有真实审核资料，账号和用户输入为合成；不把工程验证称为真实学生在线试用。
