## 表设计：为什么是这些列、为什么没有"自由文本列"

列集合与白名单维度**逐一对应**（8 个）：`route`、`retrieval_profile`、`generator_profile`、`handoff_required`、`failure_category`、`latency_bucket`、`estimated_cost_bucket`、`event_date`（+ `id`、`created_at`，实测共 **10 列**）。

- **能回答四个问题**：哪条链路＝`route`（五级结论）+ 两个 profile（哪套检索/生成栈）；哪一级路由＝`route`；命中/降级/转人工＝`failure_category`（`NONE` 为正常命中）+ `handoff_required`；耗时＝`latency_bucket`（**只落桶，不落精确毫秒**——精确值可参与指纹化）。
- **没有的列**：`message` / `question` / `answer` / `student_id` / `name` / `contact` / 密钥 / 逐条散列——一个都没有。隐私边界靠"列本身不存在"兜底，而不是靠应用层自觉。
- **耗时为什么用桶**：精确耗时与"同一秒内的两条记录"结合可参与指纹化，桶化后只保留运维所需的分布信息。
- **为什么没有"按人/按会话"的索引**：本表根本没有可归人的维度，建这类索引只会诱导后续往里加标识。

## 双向闸门（应用层 + 表层）

1. **应用层**：写入前调用既有 `PrivacyBoundary.anonymousTelemetry`——白名单外字段直接抛 `IllegalArgumentException`，取值形态（代码维度 `^[A-Z][A-Z0-9_]{0,63}$`、profile `^[A-Za-z0-9._-]{1,128}$`、布尔、ISO 日期）逐项校验；**校验全部发生在写库之前，被拒调用零副作用**。
2. **表层**：`route`/`failure_category`/`latency_bucket`/`estimated_cost_bucket`/两个 profile 上都有复刻白名单形态的 `CHECK`——**即使绕过应用层直接写库，自由文本也进不去**（用例已实证）。

## 能说明什么、不能说明什么

- **能说明**：遥测表只承载白名单维度、双向闸门都有效、写入无副作用、迁移可干净应用。
- **不能说明**：**尚无任何真实链路在调用它**——本批没有接线（不含 HTTP/路由侧上报），因此"链路命中/降级/转人工会被自动记录"尚未发生；接线属后续批次，需先确认在哪些层记录（避免把遥测塞进共享控制器）。

## 批2：本机管理端只读聚合（CX-1，2026-09-22）

### 对外契约与最小暴露面

新增受既有 `zhku-local-admin` profile 与 `zhku.local-admin.enabled=true` 同样条件保护的只读地址：

```text
GET /zhku/local-admin/telemetry/aggregates?dimension=route&from=2026-08-23&to=2026-09-22
```

- `dimension` 缺省为 `route`，仅允许 `route`、`failureCategory`、`handoffRequired`、`latencyBucket`、`eventDate`。枚举同时固定 SQL 列名，不能由请求参数拼接 SQL。
- `from` / `to` 缺省时取当天（UTC）及其前 29 天，首尾包含共 30 日；分母仅为该日期窗口内事件总数。
- 每个桶只含「所选维度值、`count`、`ratio`」三键；`ratio=count/窗口总数`，按 `HALF_UP` 保留四位小数。结果按 `count` 降序，计数相同按桶值稳定升序（空值末尾）。无数据返回 HTTP 200 与 `[]`。
- 输出必须经过 `PrivacyBoundary.telemetryAggregateExport`：该遥测专用白名单拒绝未审核维度，并且只复制上述三键。接口没有、也不会新增按 `id`、会话或单条事件读取的路由。

该读取侧只依赖 V17 的表结构，不改 `telemetry/` 写入仓储、迁移、前端、评测或 YAML。管理端不能借聚合接口返回 `message`、`question`、`answer`、`studentId`、`name`、`contact`、`apiKey`、事件 ID、匿名散列或去重键；这些字段既不在表中，也不在输出白名单中。
