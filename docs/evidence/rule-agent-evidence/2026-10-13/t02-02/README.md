## 解决的问题与实现边界

1. 检索候选不能直接冒充已核验事实：RuleAgentEvidenceTools将SEARCH候选与READ核验事实分开，复用实际词法检索、当前原文reader、跨度/hash验证和引用审计。
2. 句柄不能跨主体、任务或目录版本复用：候选绑定owner/task/目录版本和5分钟期限；任务15分钟后原文令牌失效。撤回资料会使既有原文和读取失效。期限沿T01防御预算，不是业务服务承诺。
3. 未命中不能冒充处理失败或规则不存在：健康未命中返回NO_MATCH；检索、读取和审计异常返回UNAVAILABLE且无可发布事实。材料资格或版本变化返回REJECTED/EVIDENCE_CHANGED。
4. 第4条已有分类事实不能说明修读差异：新增两项一般修读解释，用户已确认T02-D01/D02及边界。增量覆盖层单独版本化，原B02/B03及旧回放材料不改写。精确引文跨度分别26..48、49..78。

工具不负责理解自然语言、判断当前问题是否完成或决定个人适用性。READ返回的是供T03进一步选择和约束的核验事实，不是学生最终答案。原文令牌仅为内部工具能力，尚未接入学生HTTP接口。

## 上轮卡点的真实根因

运行诊断显示第4条正文及0..78跨度均与审核输入相同，差异是SHA-256字符串表示：发布器输出大写，草案保存小写。RuleArticle4Overlay原先使用区分大小写的equals，误判原文不可用。

- [实际目录诊断](../t02-tools-db-03-diagnostic/catalogue-binding-diagnostic.json)：S02/GENERAL绑定具有相同正文、跨度和大写摘要。
- [发布器](../../../../../knowledge/src/main/java/com/zhku/knowledge/publication/ReviewedKnowledgePublisher.java)：checksum函数采用toUpperCase。
- [失败回归](../t02-digest-red-01/results.json)：34项中大写绑定用例发生1个错误，其他检查通过。
- 修复仅将两处摘要比较改为equalsIgnoreCase，保留审核快照指纹、批准状态、完整原文跨度和新增引文逐字匹配；实际摘要变化和跨度变化仍拒绝。

先前两次失败及到期退出记录保留，见../t02-01/README.md；没有重写为成功。
