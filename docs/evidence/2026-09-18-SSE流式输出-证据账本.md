# SSE 流式输出证据账本

日期：2026-09-18
范围：本机预览会话消息的 SSE 传输；第五次合并 `1573507`（实现提交 `04d9ab6`）。

## 交付与边界

- 地址不新增：仍为 `POST /api/zhku/local-preview/conversations/{sessionId}/messages`；
  客户端以 `Accept: text/event-stream` 协商 SSE，无该 Accept 时保持原 JSON 响应。
- 事件依次为 `accepted`、`reply`、`complete`。`accepted` 仅给出会话快照，
  `reply` 与 `complete` 复用同一轮作答；这不是模型 token 级流式输出。
- `SseConversationStreamer` 在有界后台执行器中调用既有会话门面，处理器不直接写会话存储，
  因而不会绕开既有的 revision、会话状态和五级路由保护。

## 事件载荷实际形态

```json
event: accepted
data: {"sessionId":"…","revision":0,"conversationStatus":"ACTIVE","type":null,"message":null,"answer":null,"route":null,"handoffRequired":false,"citationIds":[],"citations":[]}

event: reply
data: {"sessionId":"…","revision":0,"conversationStatus":"ACTIVE","type":"ANSWER","message":"…","answer":null,"route":"RETRIEVAL_AUGMENTED","handoffRequired":false,"citationIds":["cit-…"],"citations":[{"citationId":"cit-…","sourceTitle":"公共选修规则手册","sourceLocator":"第 1 页","pageNumber":1}]}

event: complete
data: {"sessionId":"…","revision":0,"conversationStatus":"ACTIVE","type":"ANSWER","message":"…","answer":null,"route":"RETRIEVAL_AUGMENTED","handoffRequired":false,"citationIds":["cit-…"],"citations":[{"citationId":"cit-…","sourceTitle":"公共选修规则手册","sourceLocator":"第 1 页","pageNumber":1}]}
```

| 字段 | 当前实际下发 | 说明 |
| --- | --- | --- |
| `route` | 是 | `reply`/`complete` 透传会话门面的五级路由结论；`accepted` 为 `null`。 |
| `handoffRequired` | 是 | `reply`/`complete` 透传；`accepted` 固定 `false`。 |
| `citationIds` | 是 | `reply`/`complete` 透传不透明引用标识；无检索增强时为 `[]`。 |
| `citations` | 是 | `reply`/`complete` 原样透传同步回复的来源明细；与 `citationIds` 长度恒等、顺序一致，`accepted` 为 `[]`。 |

> 约束：会话不存在时快照没有可见状态，`revision` 与 `conversationStatus` 为 `null`；
> 不伪造状态，客户端应以 `type=SESSION_INVALID` 和 `handoffRequired=true` 处理。

## 配置键

均仅在 `zhku-local-preview` Profile 和 `zhku.local-preview.enabled=true` 下生效：

| 键 | 当前值 | 语义 |
| --- | --- | --- |
| `zhku.streaming.enabled` | `true` | 显式注册 SSE 处理器；关闭时原同步 JSON 接口仍可用，SSE 请求返回可读的 `503`。 |
| `zhku.streaming.timeout-millis` | `30000` | 单条 emitter 的超时上限，必须为正数。 |
| `zhku.streaming.worker-threads` | `2` | 固定后台作答线程数。 |
| `zhku.streaming.queue-capacity` | `16` | 有界等待队列容量；满载采用拒绝策略，不无限积压请求。 |

## HTTP 内容协商 P0-lite 修复（2026-09-21）

### 根因、RED 与最小修复

`ZhkuLocalPreviewConversationController.streamMessage` 原先声明 `ResponseEntity<?>`，使 Spring MVC 对 body 只能看到 `Object`，不会交给 `ResponseBodyEmitterReturnValueHandler`；请求携带 `Accept: text/event-stream` 时回退消息转换器并报 `No converter for SseEmitter`。

先新增控制器 HTTP 回归：真实 `SseConversationStreamer` 使用同步测试执行器，经 MockMvc 在同一消息地址协商 SSE。RED 结果为预期的 **HTTP 500**（断言期望 200、实际 500），且日志包含上述转换器错误。最小修复将成功返回值收窄为 `ResponseEntity<SseEmitter>`；空消息与流能力不可用/队列拒绝改由控制器 `@ExceptionHandler` 返回原有 JSON 400/503 契约。

GREEN 聚焦命令：

```powershell
mvn -pl knowledge "-Dtest=ZhkuLocalPreviewConversationControllerTest,ConversationStreamProcessorTest,ZhkuLocalPreviewStreamingConfigurationTest" test
```

结果：**14 passed / 0 failed / 0 errors**。其中新 HTTP 用例确认 `Accept: text/event-stream` 得到 200 和 `accepted → reply → complete`；另有显式 `Accept: application/json` 断言，防止同地址 JSON 分支被 SSE 修复误伤。

最终执行 `mvn -pl knowledge test`：**349 passed / 0 failed / 0 errors / 4 skipped**，`BUILD SUCCESS`。4 项跳过均为既有 opt-in/条件守卫；本修复未新增跳过。
