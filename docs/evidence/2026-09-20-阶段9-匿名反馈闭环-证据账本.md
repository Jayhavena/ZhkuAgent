# 阶段 9：匿名枚举反馈闭环证据账本

> 状态：**已交付，等待验收**。本记录覆盖线 B 的匿名反馈、90 天保留聚合和本机管理员最小审核 API；不含 WB-1 的管理员界面、线 A 的办事清单/答案卡，也不覆盖学生侧预览 HTTP 装配。

## 交付与边界

| 项目 | 记录 |
| --- | --- |
| 个人负责范围 | `com.zhku.knowledge.feedback`、`V16__create_anonymous_feedback.sql`、本机管理员聚合读取/显式保留 API |
| 迁移 | 单一 `V16`；事件表与聚合表自包含，不对线 A 的 V15 建外键。清单标识与版本只是软引用 |
| 可接收输入 | 清单标识、版本、封闭原因枚举、64 位匿名会话散列；请求字段手工白名单，未知字段一律拒绝 |
| 短期事件 | 仅保存散列、去重键、枚举、创建和到期时间；按同一 UTC 自然日去重 |
| 到期处理 | `Clock` 到达创建时刻 + 90 天时，按清单软引用/版本/原因/创建日汇总，并以 JDBC 事务累加聚合后删除事件 |
| 管理员视图 | 只返回 `guideIdentifier`、`guideVersion`、`reason`、`feedbackDate`、`count`；日期固定为 ISO 字符串 |
| 明确不做 | 不收集原问题/原回答、自由文本或学生身份；不接工单、短信、邮箱、校务系统；不自动改检索排序、提示词、制度结论、资料发布或索引；不自动创建资料候选 |

V16 的两张表均不存在 `message`、`student_id`、`name`、`contact`、`question` 或 `answer` 列。迁移只增加反馈专用表，没有修改既有迁移或共享数据模型。

## API 契约

### 匿名反馈边界

`POST /zhku/feedback`

```json
{
  "guideIdentifier": "course-selection",
  "guideVersion": "2026-1",
  "reason": "OUTDATED",
  "anonymousSessionHash": "<64 位十六进制散列>"
}
```

首次接收返回 `201`，同日重复返回 `200`。两者均只返回：

```json
{"accepted": true, "duplicate": false}
```

回执不会返回匿名散列、去重键或事件 ID。`message`、`studentId`、`student_id`、`name`、`contact`、`question`、`answer` 等字段被拒绝，且不会到达仓储。

该控制器是已测试的反馈边界；学生侧本机预览应用目前只扫描 `com.zhku.knowledge.web`，本轮为遵守冻结共享装配约束未改变其扫描范围。因此它**不能说明**预览问答页已可提交反馈；该接线须在负责方登记共享 HTTP 装配后完成。

### 本机管理员 API

- `GET /zhku/local-admin/feedback/aggregates`：返回仅含清单软引用、版本、原因、ISO 日期、计数的数组。
- `POST /zhku/local-admin/feedback/retention`：管理员显式执行到期聚合，返回 `{"aggregatedEventCount": 3}` 形式的计数；不发布资料、不创建候选、不触发索引。

控制器只在 `zhku-local-admin` profile 与 `zhku.local-admin.enabled=true` 下装配。管理员界面由 WB-1 负责，本交付没有修改任何前端资源。

```powershell
$env:ZHKU_DB_PASSWORD = [Environment]::GetEnvironmentVariable('ZHKU_DB_PASSWORD', 'User')
```

TDD 过程的 RED 证据：

1. `AnonymousFeedbackContractTest` 先因反馈模型、仓储、服务和控制器不存在而编译失败；最小实现后转绿。
2. 首轮 PII 用例发现测试辅助 JSON 发生双重转义，400 来自解析器而非白名单。先将“第二个字符必须是 JSON 引号”写成失败断言，再只修正构造字符串；修正后 PII 用例真实抵达并由白名单拒绝。
3. `FeedbackRetentionTest` 先因聚合模型、清理服务和仓储方法不存在而 RED；补齐最小实现后转绿。
4. `FeedbackAdminControllerTest` 先因查询服务与控制器不存在而 RED；实现后发现独立 MVC 默认把 `LocalDate` 序列化为数组，响应 DTO 改为显式 ISO 字符串后转绿。

## 全量回归说明

执行 `mvn -pl knowledge test` 时，反馈四类测试均通过，但全模块结果为**失败**：共 3 个既有资料问答/检索验收类出现 14 项失败。

- `PublicElectiveGroundedAnswerAcceptanceTest`：9 项中 6 项失败；资料定位符与共享演示数据不一致或证据不足。
- `PublicElectiveKeywordSearchAcceptanceTest`：11 项中 7 项失败；同样的期望定位符不匹配。
- `JdbcRetrievalIndexingTest`：3 项中 1 项失败；期望合格片段数 2、实际为 4。

这些失败均在 `answer/`、`publication/`、`retrieval/` 既有验收范围；线 B 的反馈测试没有修改这些包，也不写入其表。`JdbcFeedbackRepositoryTest` 每例使用随机清单标识，并在结束后仅删除自己两张反馈表中的行。故本账本不把全量回归误报为通过，也不越权修改线 A 的资料/检索验收数据。

## 能说明与不能说明什么

可以说明：匿名输入被严格限制为散列与枚举；重复反馈可去重；90 天边界可聚合删除；V16 没有身份/文本字段；本机管理员 API 只读取聚合并显式执行保留。

不能说明：学生侧页面已接线、管理员 UI 已完成、真实学生已使用、反馈能自动转化为资料候选、全模块共享演示数据回归通过，或系统已接入任何外部校务/通知渠道。
