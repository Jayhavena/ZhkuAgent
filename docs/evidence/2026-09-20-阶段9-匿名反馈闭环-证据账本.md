## API 契约

### 匿名反馈边界

`POST /zhku/feedback`

```json
{
  "guideIdentifier": "course-selection",
  "guideVersion": "2026-1",
  "reason": "OUTDATED",
  "anonymousSessionHash": "<64 位十六进制散列>"
}
```

首次接收返回 `201`，同日重复返回 `200`。两者均只返回：

```json
{"accepted": true, "duplicate": false}
```

回执不会返回匿名散列、去重键或事件 ID。`message`、`studentId`、`student_id`、`name`、`contact`、`question`、`answer` 等字段被拒绝，且不会到达仓储。

该控制器是已测试的反馈边界；学生侧本机预览应用的接线结果见本账本末尾的“预览接线补充证据”。

### 本机管理员 API

- `GET /zhku/local-admin/feedback/aggregates`：返回仅含清单软引用、版本、原因、ISO 日期、计数的数组。
- `POST /zhku/local-admin/feedback/retention`：管理员显式执行到期聚合，返回 `{"aggregatedEventCount": 3}` 形式的计数；不发布资料、不创建候选、不触发索引。

控制器只在 `zhku-local-admin` profile 与 `zhku.local-admin.enabled=true` 下装配。管理员界面由 WB-1 负责，本交付没有修改任何前端资源。

## 全量回归说明

执行 `mvn -pl knowledge test` 时，反馈四类测试均通过，但全模块结果为**失败**：共 3 个既有资料问答/检索验收类出现 14 项失败。

- `PublicElectiveGroundedAnswerAcceptanceTest`：9 项中 6 项失败；资料定位符与共享演示数据不一致或证据不足。
- `PublicElectiveKeywordSearchAcceptanceTest`：11 项中 7 项失败；同样的期望定位符不匹配。
- `JdbcRetrievalIndexingTest`：3 项中 1 项失败；期望合格片段数 2、实际为 4。

这些失败均在 `answer/`、`publication/`、`retrieval/` 既有验收范围；线 B 的反馈测试没有修改这些包，也不写入其表。`JdbcFeedbackRepositoryTest` 每例使用随机清单标识，并在结束后仅删除自己两张反馈表中的行。故本账本不把全量回归误报为通过，也不越权修改线 A 的资料/检索验收数据。

## 阶段 10 第 6 项补充：隐私、密钥与保留检查（2026-09-21）

本补充新增 `com.zhku.knowledge.privacy.PrivacyBoundary`，作为遥测、配置回显和聚合导出的窄边界；只新增该包并对 `FeedbackRetentionService` 加一道服务层到期复核。未创建迁移，未改 `rag/`、`application-*.yml`、前端或评测集。

| 边界 | 实际白名单 / 行为 |
| --- | --- |
| 匿名结构化遥测 | 只允许 `route`、检索/生成 profile、`handoffRequired`、失败类别、延迟桶、成本桶和 ISO 日期；未知字段直接拒绝，代码型维度与 profile 另做格式校验，不能把原问题伪装进允许字段的值中 |
| 配置回显 | 只复制 `provider`、`model`、`profile`、`status`；`apiKey`、`ZHKU_DB_PASSWORD` 和任何未来未审核字段均被丢弃，不会透传值 |
| 聚合导出 | 固定为 `guideIdentifier`、`guideVersion`、`reason`、`feedbackDate`、`count`；不含逐条散列、去重键、原问题、原回答或身份字段 |
| 90 天保留 | `now >= expiresAt` 才进入聚合删除；即使仓储错误返回尚未到期行，服务层仍会二次过滤，避免提前删除匿名明细 |
