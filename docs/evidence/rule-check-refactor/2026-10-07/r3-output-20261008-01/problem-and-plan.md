## 问题与决策

| 问题 | 改动 | 验证 |
| --- | --- | --- |
| `asText/asDouble/asBoolean(false)`掩盖错误类型或缺handoff | 先检查根对象和四字段类型，再读取；非法输入统一格式异常 | parser独立字段反例及回环适配器 |
| Java null/空文本可能产生非受控异常 | 在读取前拒绝null/空白 | 检查格式异常类型 |
| 非有限/越界分值可被构造或解析 | parser与guard均验证有限0–1 | JSON溢出与直接NaN/Infinity/越界反例 |
| 空白回答/空引用仍可通过guard | 下发前拒绝空正文、空引用及空白引用项 | 直接构造，包含白名单本身有空ID的夹具 |
| 仅测组件无法证明下游降级 | 扩展composer和现有Spring AI回环适配器测试 | 检查DECLINED、稳定文案、空引用与handoff |
| 注释把有限短语检查写成通用事实控制 | 改成准确的结构和短语边界说明 | 单独保存4→40语义缺口，不关闭RC-04-SEMANTICS |

保留ModelResponse四字段、既有0.5自报分值门限和调用方兼容。该分值不是校准过的正确概率。解析器允许空引用的转人工响应存在，守卫禁止其作为答案下发；引用标识原样保留，不trim后伪造白名单匹配。未引入依赖或修改POM、模型提示、数据库、学生协议。

追加范围：`GroundedAnswerComposerTest`、`SpringAiAdapterContractTest`与验收入口单元白名单。后者只绑定127.0.0.1随机端口，使用固定虚构key，AfterEach停止服务。没有将真实供应商测试纳入入口。

## 风险、限制与回退

严格类型检查可能让以前被自动转换的供应商输出更多降级，这是预期行为；真实供应商格式违约比例未测。既有0.5阈值未校准，不能用此修复证明回答可靠。没有新增重复键、尾随JSON、额外字段的拒绝政策；本批“严格”指计划定义的字段结构合同，不是完整JSON Schema实现。
