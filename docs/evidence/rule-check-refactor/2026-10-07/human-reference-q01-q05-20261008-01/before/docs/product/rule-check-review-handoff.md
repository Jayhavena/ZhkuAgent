# 校园规则查证：资料审核与评估接续包

2026-10-08。当前工程准备已完成，以下均为待填写/待审核项，不是已批准政策或用户实验记录。用户已授权连续实施；这些证据补齐后按既有计划接续，不必再逐任务授权。

## 1. 资料门禁需要的最小记录

先确认一个主题即可，候选仍为公共选修规则。参见[来源核验](../evidence/rule-check-refactor/2026-10-07/r0-baseline-01/source-audit.md)。用户已确定首轮以2025版为准，使用既有2025快照与AI辅助候选作核对起点。回答标明2025依据；不自动推断2026现行性。2026全文不再是这一范围试验的前置条件。

| 字段 | 待补证据 |
| --- | --- |
| sourceId / 官方发布地址 | 可独立找到的来源，不用模型生成URL |
| 原始完整文件 / SHA-256 | 完整资料快照，记录取得时间与字节指纹 |
| revision / 文号 / 发布机构 | 来源明确声明的版本身份，不能仅用下载年份替代 |
| 适用对象 / 学年 / 有效期 | 来源明示的范围；未知、无上限分别记录 |
| 新旧关系 | 哪些条款变更、取代或仍适用；争议标未确认 |
| student visibility / sharing qualification | 走资料审核记录；官网下载成功不能自动改为true |
| 审核人 / 日期 / 结论 / 理由 | 实际审核责任与证据，不填虚构审核者 |
| page / locator | 分开PDF物理页、印刷页、节/条及可核对原文 |

完整手册无需一次发布全部内容。先审核本主题必要条款、相关例外与其引用依赖；跨页条款必须合并对照，空白/提取错页需回到原件核验。

## 2. 一条审核规则的记录模板

以下字段保持空缺直到对照有效来源完成审核，不从历史草稿自动复制成正式规则。

```json
{
  "ruleId": "TODO",
  "reviewStatus": "PENDING_REVIEW",
  "reviewer": null,
  "reviewedAt": null,
  "applicableScope": [],
  "requiredConditions": [],
  "confirmedFacts": [],
  "exceptions": [],
  "forbiddenConclusions": [],
  "evidenceBindings": [],
  "unresolvedConflicts": [],
  "missingDependencies": []
}
```

每个事实/条件/例外分别绑定source/chunk、revision、checksum、原文位置与文字。重要条件未知则追问或说明缺证；局部摘录不能推成完整个人资格。没有受理回执不能说办理已受理。资料冲突未解决不能挑一个来源肯定作答。

审核规则用于决定新v2的五种业务状态；现有原文组件只检查摘录和当前存储字段，不替审核者决定相关性、条件/例外完整性及适用性。

## 3. 人工参考与评分准备

2026-10-08已整理[开发集20题核对清单](rule-check-2025-human-reference-development.md)、[原文对照](rule-check-2025-source-excerpts.md)及可回填的结构化记录。原件指纹本轮匹配，PDF页76–77实际提取；所有人工核对字段仍留空，报告候选未纳入该工作表。

- 对照原文复核[36题候选](../evidence/rule-check-refactor/2026-10-07/r0-baseline-01/quality-cases-draft.json)及[独立风险草稿](../evidence/rule-check-refactor/2026-10-07/r0-baseline-01/risk-cases-draft.json)。保留错误与争议，不凑齐“通过”数量。
- 每题写预期状态、必要原子事实、条件/例外、所需证据、允许未知项及不可说结论。部分回答必须独立成立；必要追问与重复无用追问分别评分。
- 按条款/问题家族划分20开发与16报告，记录谁接触过哪些题、调优用途和污染；AI助手已经查看的候选不能宣称盲测。必要时另采独立报告题。
- 先人工核对评分一致性，语义评分不靠JSON校验；模型裁判未来先校准再影子评分。分开检索漏证、证据使用错误和执行错误。
- 冻结题集、来源及rubric指纹后再比较版本。保存逐题改善/退步/未知；小样本门槛不等于总体成功率或显著提升。

## 4. 接续开发顺序与验收

1. B-01/B-02解除后，Task2接入已审核规则与现有混合检索，新v2只输出模板事实或核验原文，复用身份、CSRF及引用审计。
2. 验证学生请求不能提交server快照自证资格；当前reader以受控服务端配置重读，覆盖账号、撤回、版本及输出流程。仍需处理读后下发窗口，不能将顺序数据库测试当并发保证。
3. Task3真实浏览器验证回答、部分回答、必要澄清、缺证、冲突及原文定位；原学分v1兼容保留。
4. Task4执行锁定16题质量评估及5–8位真实目标用户对照官网/PDF。平衡题组/顺序，报告正确完成、耗时、失败和未知；实际重复调用/用量/成本另记。
5. 依据[Eval约定](rule-check-eval-contract.md)和[主路线图](../superpowers/plans/2026-10-07-rule-check-refactor-roadmap.md)作继续/调整/收缩判断，G2未通过不扩张多主题或P2设施。

开发恢复先读[卡点表](rule-check-blockers.md)、[R5计划](../superpowers/plans/2026-10-08-rule-check-r5-plan.md)、执行账本和最新issues.json。历史验收仅对应当时源码快照；用新批次复核受影响路径，不覆盖旧失败记录。
