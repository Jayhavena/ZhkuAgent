# 校园规则查证 Eval 约定

版本：1.0；日期：2026-10-07。状态：**评估设计，尚未实施或跑出产品成绩**。本约定把用户提供的 [AI系统评估笔记](../tutorials/AI系统评估-字幕整理与实践思路.md) 转成项目评估要求，不重写教程、不新增评估框架或裁判供应商。

产品成功与五种回答状态以 [范围约定](rule-check-scope.md) 为准；阶段执行见 [路线图](../superpowers/plans/2026-10-07-rule-check-refactor-roadmap.md)，证据归档见 [证据规范](../evidence/rule-check-refactor/2026-10-07/README.md)。本文件补充评分可信度、分层诊断、比较不确定性与重复可靠性；原有确定性验收继续保留。

## 1. 先定义成功，再证明改动有用

评估闭环：**定义成功 → 收集与核对案例 → 运行并保留必要记录 → 分维度评分 → 分析失败和不确定性 → 修改后配对比较。**

每次评估分别回答：

1. 当前系统在这些任务上完成了什么，有哪些错误？
2. 评分依据是否可靠，模型裁判可能漏掉什么？
3. 新版改善了哪些任务、退步了哪些任务，证据是否足以确认变化？

达到样本门槛与证明版本提升是两个结论。小规模报告可支持继续有限试验，不能自动支持全校质量、生产放行或收益承诺。

目前 `knowledge/src/main/java/com/zhku/knowledge/eval/EvaluationRunner.java` 对比路由、引用位置和拒答等，具备版本清单核对；本轮读取的执行器没有逐主张评分、裁判校准或配对统计。此结论只针对该执行器，不宣称已审计全仓所有评测资产。后续扩展独立查证评估层，保留旧契约。

## 2. 数据资产分工

| 集合 | 用途 | 使用边界 |
| --- | --- | --- |
| 质量开发集 | 查证问题探索、调检索/提示词、错误分析 | 可反复使用；不能作为未见报告集 |
| 质量报告集 | 冻结后比较产品版本 | 不用于选提示词、改评分器或挑模型；一旦用于这些用途就登记污染并换新报告集 |
| 高风险边界集 | 数字/对象/例外、越权、撤回、冲突、重复提交等约束 | 独立回归，已知攻击夹具不能冒充真实问题分布 |
| 评分器调优/验证集 | 用人工标注检验裁判漏判、误判与未知 | 按原任务家族分组拆分；不能把产品报告集用于调裁判后继续报告其未见效果 |

规模沿用小步路线，但校正用途：

- 单主题36个质量案例：20开发、16报告。高风险反例独立保存，不混进16题后宣称真实流量准确率。
- 三主题120个产品案例：90质量（每主题30，其中14开发、16报告）+30高风险边界。即42质量开发、48质量报告、30边界；替换原混合的72/48划分。
- 首次人工错误分析可查看30–50条相关输出，用于发现失败，不是上线质量证明。若新查证链尚无输出，先用获授权的可比基线，或在R5运行后补齐，禁止编造“已有输出”。
- 裁判验证输出另计，不为凑数将其当成新的产品问题；每条保留parentCaseId和是否人工构造错误变体。

每主题30题先覆盖完整/部分回答、澄清、缺证与冲突。尚无真实问题分布时标记 `samplingStatus=EXPLORATORY`，不把等量主题或合成样本称为代表性用户流量；后续按来源与实际问题分布补样，合并需说明权重。

同一原始问题的改写、同一条款上的近重复、同用户任务家族不得跨开发/报告集。保留documentGroup、clauseGroup、questionFamily和userStudyGroup作泄漏与聚类检查。语料库保留待查证规定，隔离的是调优查询与报告查询；不是把目标规定从RAG库删除。

资料更新时保存旧评估快照，新版本重审受影响参考答案；不可用过期金标准把正确新版判错，也不可混用新旧口径比较。

## 3. 分层评分与失败定位

| 层面 | 核心检查 | 证据来源 |
| --- | --- | --- |
| 检索 | 有资格的支持条款、条件和例外是否找到；hit@K、Recall@K、无关上下文、旧版/内部材料 | 人工确认必要条款集合、实际候选与版本 |
| 回答 | 结论支撑、对象/时间/数字、条件例外、必要澄清、部分回答未知项、问题相关性 | 最终答复、原文跨度、审核规则、人工标注 |
| 执行 | 真实工具参数/返回、允许行为、状态与答复一致、预算/取消/归属、最终效果 | 程序断言、轨迹、归档/数据库或资源观察 |

普通只读查证的执行成功以回答状态、资料资格与原文展示约束为准；不为套用Agent基准增加模拟教务办理。任务确实有工具/状态变化时才验证对应最终状态，系统日志与归档等允许写入需与禁止的教务业务写入分开。

明确记录两种情况：应有证据却没有召回，系统因此拒答，可以通过“失败时没有编造”的安全检查，但用户任务仍未完成；本来就没有充分依据时，正确缺证/澄清可以是任务成功。不能统一将所有拒答记为成功或失败。

hit@K只要求至少命中一项，Recall@K检查必要证据集合；只命中主条款而漏例外不能算充分证据。忠实于错误/过期材料仍可能错，资料资格单独校验。

## 4. 原子评分标准

每项输出 PASS / FAIL / UNJUDGEABLE / ERROR、严重程度、答案片段、证据位置、理由及评分方式。下面是首轮rubric，实际条款金标准由审核者核对。

| ID | 问题 | 首选评分方式 |
| --- | --- | --- |
| E01 | 格式、字段类型、引用身份是否有效？ | 代码 |
| E02 | 资料是否审核、可见、有效且未撤回？ | 代码读取真实元数据 |
| E03 | 必要支持条款和例外是否召回？ | 金标准集合与实际候选比较 |
| E04 | 每个实质主张是否被引用原文支持？ | 摘录/模板代码校验；自由解释人工，裁判辅助 |
| E05 | 数字、日期、适用对象、否定词与条件是否一致？ | 结构化事实代码校验+语义人工 |
| E06 | 是否遗漏会改变结论的条件/例外？ | 人工；已校准裁判辅助 |
| E07 | 部分回答是否独立成立、未知项明确，没有暗示整体资格？ | 人工与状态合同 |
| E08 | 澄清是否必要、无重复，缺证/冲突状态是否正确？ | 代码与人工 |
| E09 | 是否回答实际问题，原文是否可定位？ | 人工相关性+真实定位检查 |
| E10 | 是否虚构审批/受理或进行禁止操作，答复是否与真实状态一致？ | 程序结果/最终状态+人工承诺检查 |
| E11 | 工具、预算、取消、幂等、身份与资源退出是否符合合同？ | 现有工程测试与实际观察 |
| E12 | 用户正确完成、耗时、失败/超时与下一步是否有记录？ | 用户对照数据 |

关键维度不能被其他高分抵消；语气、长度与满意度单独作体验信号，不替代任务成功。案例可以含多个失败标签，失败标签总数不等于失败案例数。

裁判不可判断或请求/解析失败不是产品已失败，也不是已通过：独立记录评估失效，并人工复核。未解决样本不计作确认通过；报告评分覆盖率、已确认通过/总样本与未知数量，禁止仅删除未知样本后呈现漂亮通过率。

## 5. 先验证评分器

首个36题试验中的16题报告由人工依据审核原文逐项评分，确定性条件由代码验证。没有校准证据时，模型裁判仅旁路给建议，不作为唯一放行依据。

裁判校准步骤：

1. 人工初标并复核争议，锁定原文、规则和标签。自己初标的限制如实记录；不把同一模型生成的答案自动当金标准。
2. 收集正例、错误数字/对象、遗漏例外、误导性部分回答、合法拒答和无法判断案例；构造变体单独标合成，不解释为实际错误频率。
3. 按任务家族分开裁判调优和验证组，冻结rubric/模型/提示词；隐藏系统版本，语义对照交换答案顺序。
4. 逐项计算人工参考与裁判的混淆矩阵：TP=坏答案正确检出、FN=坏答案漏放、FP=好答案误拦、TN=好答案放行。
5. 报告检出率TP/(TP+FN)、漏放率FN/(TP+FN)、误拦率FP/(FP+TN)、一致率、κ、无法判断率和解析错误率；分母为0时记N/A，不写0%完美。
6. 按错误类型和严重程度拆分，报告原始计数与区间。关键坏例漏放后不准作为该维度自动放行裁判；其他类别也依据事前风险标准评估，κ不设置通用0.6/0.8阈值。

低样本、争议、裁判失效或高风险案例保持人工复核。专用支持性检测器/NLI、多裁判面板属后续候选，需在本领域验证；不是立即增加新框架或认为投票保证正确。

产品模型、资料域、评分标准、裁判模型/Prompt变化后，重核受影响金标准并重新校准。旧裁判分数与新裁判分数不可直接作为产品改善差值。

## 6. 新旧版本怎么比较

一次比较尽量只改一个主要因素；固定问题、可比的知识快照、身份/初态、预算和评分标准，并记录所有同时变化项。裁判若改变，应将新旧输出用同一冻结标准重评分，区分产品与评分器变化。

逐案例保留：都通过、都失败、新版改善、新版退步、未判定。二元成功配对差值为 `(改善数量−退步数量)/配对总数`；未判定先复核，不能当作一方失败凑差值。

报告总体与分主题/状态/严重程度结果、差值区间、主要退步ID。单次二元通过率可在合理独立假设下报告Wilson区间；同条款/文档、同用户、多次同题不能全部视为独立样本，需匹配聚类分析。聚类太少时明确不确定性，不输出假精确功效。

说明性复算：15/16=93.75%，独立二项假设下95% Wilson区间约71.7%–98.9%。**这不是本项目实测**，也不能将便利样本直接推广到用户总体；只是说明15/16并不能证明真实成功率稳定超过90%。区间方法参考 [NIST](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

比较阶段预先登记主要指标、业务关注差异、样本/聚类假设、显著性水平与功效要求；无法合理估计检测能力就记录未知，不使用“60题能检测12点”等固定结论。配对/聚类分析与实验规划依据 [Adding Error Bars to Evals](https://arxiv.org/html/2411.00640v1) 的思路；这是项目应用设计，不声称已完成论文实验复现。

试很多提示词/模型后挑最高分，记录尝试次数并用未用于筛选的新样本确认；不能不断查看同一报告集直到过线。未检测到差异标“尚不能确认提升”，不等于两版等效。

用户对照保留匹配难度与平衡顺序，分析按用户/任务分组。20%省时是初始目标，报告观测变化及其不确定性；小样本不能证明正确率总体不下降。成功任务耗时与失败/超时共同报告，避免仅保留容易成功的任务造成选择偏差。

## 7. 重复可靠性、成本与缓存

随机模型/工具任务选关键案例每题独立运行3–5次作为首轮诊断，执行预算事前冻结。每次重置适用初态、使用新trialId，重复提交同一幂等键是另一类契约测试，不能把重放结果当独立模型尝试。

保留逐题成功向量与真实轨迹：pass@k看k次至少一次成功，pass^k看k次全部成功。实际组别和估计方法写入报告，不从总体平均成功率直接计算其k次幂，不把相关运行计作独立新题。只读任务同样可重复观察内容稳定性，但不用强加写数据库目标。最终状态与重复可靠性的参考来自 [τ-bench](https://arxiv.org/abs/2406.12045)，不是其客服成绩在校园场景的迁移保证。

成本包含失败、重试、embedding、模型裁判及工具开销，分别报告产品执行与评估成本；总可计量产品费用/成功结果数为成功成本，成功数0时N/A。供应商usage/真实版本/费用缺失就标未知，外发预算不等于费用精确封顶。

缓存分开：

- 系统输出缓存绑定输入/上下文/初态、系统/模型参数/Prompt、资料与索引版本。
- 评分缓存再绑定输出hash、参考证据、rubric、裁判版本/参数。
- 资料可见性变化时重新检查，不能从缓存展示撤回正文。
- 重复可靠性与裁判随机稳定性试验禁用相应输出缓存；独立外发必须可核对，不能把缓存命中当重复成功。

## 8. 门禁结论分层

| 情况 | 结论与动作 |
| --- | --- |
| 已确认关键错误或不安全状态 | 阻断该版本放行，保存坏例并修复 |
| 评分器不可靠/未解决未知/证据缺失 | 评估尚未就绪，转人工或补证据；不伪造产品通过/失败 |
| 有限样本达到15/16或46/48等验收线 | 可继续有限原型阶段；仅声明当前样本通过与范围 |
| 新旧观测差值为正但区间/设计不足 | 观察到改善方向，尚不能确认提升；保留简单路径与受限试验 |
| 预登记比较有足够证据且风险不增 | 在对应样本来源与任务范围内说明改善，仍不推广全校或生产 |

零关键漏放是已知样本合同，不代表真实错误概率为零；15/16、46/48、5个百分点或20%均是项目初始决策线，不是统计检测能力。新增Agent等高复杂度主路径不能仅凭小样本分数过线启用。

运行节奏：P0确定性回归与rubric准备；R5单主题人工评估、配对报告和必要重复；R8补代表性/校准/统计与用量；真实使用后按合法采样发现新失败。模型/知识/Prompt/评分器改变时重跑受影响层，不把每次普通页面变更都变成昂贵供应商评估。

## 9. 证据记录与首轮产物

每条记录至少包含：caseId/parentCaseId、集合用途/采样性质/分组、输入与允许保留的上下文、期望状态、必要事实与禁止结论、证据版本/跨度、实际候选、最终答复、工具/状态观察、trialId、系统/资料/Prompt/裁判/rubric版本、逐项判定、人工备注、耗时与实际/未知成本。

日志仅元数据和脱敏事件；经审核的公开/合成样本或获准脱敏输出单独存为评估样本，保留评分所需答复与最小原文证据。不得将学生完整对话、密钥、Cookie或模型内部思维链写入报告；权限不足的资料仍不得进入裁判。没有保存可复核输出时，不宣称语义评分可复现。

每批新增：`cases-manifest.json`、`outputs.jsonl`、`scores.jsonl`、`errors.jsonl`、`comparison.json`；使用裁判时才生成`grader-validation.json`，进行随机重复时才生成`trials.jsonl`。文件是未来执行产物，本轮未生成假数据。

首轮最小交付：人工核对任务集、原子评分标准、一个可复核的新旧比较报告。报告固定包括质量/边界分母、评分覆盖/裁判能力、配对差异与区间/未知、退步案例、最终状态、可靠性、成本和证据强度。

RC-09增加评分可信度与版本比较证据；RC-04语义问题依然开放。本文、同步文档和规划指纹只是方案证据，不作为实际评分器或产品成绩。
