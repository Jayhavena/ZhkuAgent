# 第一包：收齐真实效果验证

用户授权：2026-10-10「推进第一包吧，直到第一包完成，但是不能一直持续太久，时刻记清楚任务是什么」。

目标：确认候选收窄后真实模型是否选对已审规则，阻断关键范围错答，处理既有词法检索干扰退步。只覆盖2025.9.2受控公共选修主题。

## 固定任务与停止条件

1. **P0 真实选题**：保留原20题和4个未评分探针。使用实际应用收窄后的候选准备请求；无候选本地拒绝，不发模型。最多一批24次外发、每题一次、无重试；另需明确授权。核对选中ID、输出状态、必要事实和原文绑定，不能只比较状态。模型探针不计人工准确率。
2. **P0 范围反例**：对象、时间、个人范围沿用已有保护，增加「已覆盖主题 + 明确未覆盖需求」反例和排除需求正控制。已知关键反例零漏放；一般规则仍能回答。有限模式不声称通用语义理解。
3. **P0 检索干扰**：原20题、21次必要条款出现，0/40/100合成干扰；比较旧词法基线和一个主要因素的改进。Recall@5目标≥90%，不得改参考、按答案加分、强制塞入必要条款。
4. **结项**：针对性回归、一次独立审查、记录结果/遗留项。达标才标通过；若实验不达标，记录失败并收缩可支持范围，不能把测试绿色当效果通过。

主动执行预算约45分钟（审批等待单独记录）。最多两轮针对性调整；不扩展页面、管理端、向量供应商调用或架构。超预算不得继续拓展实验；保留明确待完成项，不假称完成。

## 接口检查

- 任务1消费应用实际候选和已审范围；任务2改变候选准入，故先完成范围修复再固定外发字节。
- 任务1/3共用原20题及现有人工参考，均不得消费16题报告集。
- 模型只返回候选ID/null；事实、条件、范围和引用仍由服务端审核模板及真实依据决定。

## 交付

一个请求包、一份运行记录、一份结果报告及开发账本。旧证据只读；保留失败运行。工程完成与产品收益/G2分开。

Review Focus：请求候选是否来自实际应用；有无参考答案泄漏；空候选是否零外发；混合未知需求误答/误拦；检索是否按答案作弊；成功分母是否掩盖拒答和失败；旧批准是否被错误复用。
