## 解决的问题与主链路

RuleAgentRunner按“决策端给一个动作 → 白名单与参数守卫 → 实际工具 → 类型化观察 → 下一次决策”推进，不保存问句/题号到固定操作序列的映射。RuleActionBroker只连接T02规则证据工具，原文中的命令不能进入通用工具注册表。

RuleResultPublisher独立负责发布：正文来自已审核事实；事实必须确在本任务取得、当前仍可读、前提成立并符合问题对象/时间/主题范围。条件不足时使用审核过的问题追问，保留可独立确认的事实。每个主张绑定相关原文；未使用原文不放入结果。

共用runtime提供运行、步骤、工具事件、停止、清理和终止事实；等待学生结束本轮，不保留等待线程。取消后的迟到动作不执行、不发布。每轮决策端口独占，清理不能关闭宿主共享线程池。

## 失败、修复与取舍

保留所有原失败，不回改评分或参考：

2. [多子问题RED](../t03-boundary-red-02/results.json)：按读取标签隔离事实导致同任务不能复用证据。改为同task共享核验事实，每个子问题在发布前独立核对范围；50项通过。此取舍不放宽owner/task隔离。
3. [部分与事件RED](../t03-partial-events-red-03/results.json)：ASK丢弃已有独立事实，且故障工具在runtime事件上被标成成功。修正内容和执行两个层次，52项通过。
4. [审核条件反馈RED](../t03-context-red-04/results.json)：反馈缺少审核条件定义，决策替身依赖预置条件名。补充fresh规则范围、条件和缺口元数据，54项通过。

输入子问题须按顺序覆盖完整原句，允许1—4项。同任务可一次取证支持多项，避免为同一原文重复调用工具；问题拆分的语义正确性不由字符串完整覆盖检查证明。

运算首期只开放已核验第15条的严格缺课百分比阈值：操作数须来自原请求跨度，并与条款允许的操作数及比较值核对。其他格式合法的运算仍拒绝，不能当作通用计算器。

## 尚未证明与后续约束

- 决策使用可编程替身，真实供应商调用0。动态控制和真实证据链通过，不等于真实模型已能处理未预置自然问题；T05/T08负责实际验证。
- 复用的主题/适用守卫是有限中文保护，未知表达会保守拒绝。无法证明任意问句语义匹配、回答相关性或用户收益；T08必须独立评估这些维度。
- userConditions来自可信宿主的用户声明，不能从模型动作写入，也不是官方个人记录。原请求拆分、自然补充到声明的映射与跨轮版本控制由T04/T05完成。
- 决策端口必须遵守传入deadline并可取消。T03只拦截迟到动作，不承诺强制终止任意阻塞端口；T05须实测供应商工作线程与端口关闭状态。
- 供应商尝试数、已收到但被丢弃的迟到响应及最终可发布来源，须在T05与真实传输记录核对；本轮providerResponseReceived始终false，不证明在线身份统计已通过。
- 资料撤回在T02实际数据库通过，发布前仍复用fresh原文令牌核验；原文验证到外部结果保存之间的竞态收敛由T04最终发布/CAS约束处理，不能声称分布式事务原子性。
- 尚未接HTTP、学生页面或跨轮store；本轮WAITING_USER的随机凭据只是合同产物，T04才登记、授权和兑现它。
