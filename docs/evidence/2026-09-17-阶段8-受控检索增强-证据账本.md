**引用准确率 0.8750 → 0.3333 的归因（必须和数字一起引用）**：这是**分母变化**，不是召回质量退化。
`引用准确率` 的算法是"每题前 K 条候选中相关条数占比"的均值，而每题实际返回的候选数是变动的：
首份基线只有词法路，很多题只命中 1–2 条候选（分母 1 或 2），第二份基线向量路每题补满 3 条（分母 3）。
逐题算：首份 `1/2, 1/1, 1/1, 1/1` → 均值 0.8750；第二份 `1/3, 1/3, 1/3, 1/3` → 均值 0.3333。
**每道题"相关条款是否被召回、是否排第一"没有任何变化**（这正是 Recall@3 与 MRR 双双持平 1.0000 的含义）。
逐题分母已由 `[EVAL-DETAIL]` 行留痕，可复核。

**第二份基线能说明什么、不能说明什么（必须同时引用）**：

- **能说明**：① 真实 embedding 下"重建索引 → 资格过滤 → 双路召回 → RRF 融合 → 服务端引用组装"整条链路可跑通，且维度校验、索引侧与召回侧共用同一份资格过滤都在真实数据上生效（内部诱饵被强制入索引后，在真实向量路下依然一题都没被召回）；② 本机首次启用了真实索引 profile，profile 状态机（BUILDING → ACTIVE）在真实库上工作。
- **不能说明**：① **不能说明"效果提升"**——Recall@3 与 MRR 与首份完全持平（1.0000），因为该黄金集问法刻意与条款同形，**词法路本来就已经全部命中并排第一**，没有留给语义召回任何提升空间；② 引用准确率的下降是**分母效应**，既不能读成退化，也不能拿去当改进依据；③ N=4、单一小语料、单一模型，**不构成生产质量结论**；④ 本轮**没有**接入生成侧模型，回答质量完全不在本报告范围内。
- **下一步（真正能测出向量路价值的前提）**：需要一份**问法与条款不同形**的评测集（口语化问法、同义改写），否则语义召回无从体现；那属评测集版本变更，须换 `VERSION` 并在账本登记。
