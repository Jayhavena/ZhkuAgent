## 评测基线（Recall@K / MRR / 引用准确率）

**首次基线已产出（2026-09-17）**，报告行原文：

```
dataset=retrieval-golden-v1, K=3, N=4, Recall@K=1.0000, MRR=1.0000, 引用准确率=0.8750, 词法路=可用, 向量路=不可用
```

| 项 | 值 |
| --- | --- |
| 评测集版本 | `retrieval-golden-v1`（`RetrievalGoldenSet.VERSION`；冻结，改动须换版本号） |
| 分母 N | 4 个问题（每问声明相关片段集合作为分母） |
| K | 3 |
| Recall@3 | 1.0000 |
| MRR | 1.0000 |
| 引用准确率 | 0.8750（引用取每问前 3 条候选；均值） |
| 路可用性 | 词法路**可用**、向量路**不可用**（降级运行） |
| 运行装置 | `RetrievalAcceptanceEvalTest`（真实 PostgreSQL + Flyway + 真实索引/召回 SQL） |
| 复现命令 | `$env:ZHKU_DB_PASSWORD=...; .\mvnw.cmd -pl knowledge test -Dtest=RetrievalAcceptanceEvalTest` |

**这些数字能说明什么、不能说明什么（必须同时引用）**：

- **能说明**：受控词法路 + 单路降级 + 资格过滤 + 引用组装这条链路，在本机语料上对 4 个同形问法全部找回了相关条款并排在首位；内部资料诱饵在任何一题都没有被召回（资格过滤在召回侧生效）；引用准确率 0.875 的缺口来自"每题引用了前 3 条候选、其中含 1 条同源无关条款"，属召回宽度而非越界引用。
- **不能说明**：① 这不是语义检索效果——**向量路本轮不可用**（本机未配置真实 embedding profile，报告中如实标记），指标只反映"词法路 + 降级融合"；② 词法路是**受控词面匹配**（标点切分 + 长度≥2 词面包含），**不是 BM25、也不是分词检索**；评测问法刻意与条款同形，**真实学生口语问法下的召回大概率更低**；③ N=4 样本极小，不构成生产质量结论；④ 不得据此宣称"性能提升/已上线"。
- **下一步（真实基线）**：接入真实 embedding profile 后重跑同一评测集，报告 `向量路=可用` 的双路版本，并与本基线对比（同一 dataset 版本才有可比性）。

## 失败案例（本阶段已拦截场景）

- 模型引用伪造 citationId → 整答降级（GroundedAnswerComposerTest / RetrievalAugmentedAnswerServiceTest）
- 证据文本含"忽略之前的指令"注入 → 该证据失去支持力，结论降级
- 回答含"登记成功/可以免修"等办理结果断言而证据无同文依据 → 降级
- 模型超时 / 限流 / 5xx / 输出非约定结构 → 降级拒答 + 转人工
- 未发布 / 内部 / 权利未确认 / 维度不符的资料 → 索引与召回两侧均被拒

## 已知限制

- **Spring AI 依赖引入的结构性障碍（根因已取证，等确认走 B）**：用户已决策**不走 A**（隔离断言是核心资产，不得放宽）。线 A 取证结论：① 实际失败断言是 `org.springframework.ai.chat.model.ChatModel` 不可见于 knowledge 预览/治理台 classpath；② 依赖树：`knowledge → spring-ai-openai:1.0.9 → spring-ai-model:1.0.9`，而 `ChatModel`/`EmbeddingModel` 就在 `spring-ai-model`、`VectorStore` 在 `spring-ai-vector-store`（jar 类清单已核）；③ `<exclusion>` 不可行——排除 `spring-ai-model` 等于排除要用的接口；④ 装配层隔离（surefire 依赖排除）会让产物仍带 `ChatModel`，是**假绿**，比红灯更糟。结论：**断言不变 + Spring AI 进 knowledge 模块不可同时成立** → 下一步走 B（独立模块承载 Spring AI；knowledge 保持零 Spring AI 依赖，预览继续用 provider-neutral 接口 + 自实现客户端）。此前已验证通过的适配器与合同测试仍暂存 `D:\alldesk\Projects\springai-wip\`（4/4 通过，可直接迁入新模块）。
- 未接真实供应商端点；DeepSeek / Kimi / GLM / Qwen / 混元 / OpenAI 均**未通过真实合同验证**，不得声称"已支持"；预览链路的检索级默认关闭（未配置 `zhku.rag.*` 时整级跳过）。
- 索引任务目前为命令式全量重建，未接审核后的异步触发；`retrieval_index_entry.embedding` 维度不设表级约束（由 profile 切换流程 + 服务层校验保证不混用）。
- 编排器的三级处理器（澄清 / 当期通知 / 高风险规则）尚未与既有服务接线；HTTP 门面与回答卡未接线（须遵守线 B 的 HTTP 字段只追加原则；改 `ZhkuLocalPreviewConfiguration` 前需登记占用）。
- 引用审计的 `session_id` 暂留空（属线 B 会话持久化职责，避免跨线迁移顺序耦合）。
- 评测集 N=4、问法与条款同形，**不构成生产质量结论**；真实 embedding profile 接入后须用同一 `retrieval-golden-v1` 重跑并对比（见"评测基线"节的能与不能）。
