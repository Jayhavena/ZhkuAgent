# 持续开发指令（自驱循环）

> 用途：交给线 A / 线 B，让各自按计划连续开发直到阶段交付，不需要用户每步转述。
> 原则：**可以自驱，不可以越界**——遇到本指令"停止条件"里的任何一条，
> 必须停下来写状态板并上报，不得自行决策、不得猜测。
> 用户：把对应一节整段粘贴给对应会话。

---

## 一、给线 A（检索 + 生成 + 评测）

从现在起按阶段 8 计划连续开发，直到该阶段验收条件全部满足，不必每步等我确认。

**循环**（每轮都做，直到阶段完成）：
1. 先 `git merge zhkuagent-modules` 快进主线，再读 `AGENTS.md`、
   `docs/plans/agent-sync/SYNC-STATUS.md`、`docs/plans/agent-sync/持续开发指令.md`
   与 `docs/superpowers/plans/2026-09-16-stage-8-hybrid-retrieval-agent.md`；
2. 取计划里下一个未完成任务，**先写该任务对应的失败/边界测试并跑出 RED**，
   再做最小实现到 GREEN，然后跑聚焦测试与模块回归；
3. 每完成一个可独立验证的小步就单独提交（小步、可回滚），提交信息写清
   阶段与任务编号 + 覆盖的测试名；
4. 每一轮结束更新状态板你自己那行（当前任务 / 状态 / 最新提交），
   并同步文件占用声明。

**硬性边界**：
- 只改你地盘：`knowledge/.../routing/`、`.../rag/`、`.../eval/`、`answer/`，
  迁移只用 `V9`–`V11`（首用 `V9`，**不要用计划旧文里的 V7**）；
- 改共享文件（`GroundedAnswer*`、`PublicElectiveConversationRouter`、
  `LocalPreviewConversationFacade`、`ZhkuLocalPreviewConfiguration`、
  `knowledge/pom.xml`、`migration/`）前必须先在状态板「文件占用声明」登记；
- 只 stage 自己地盘的路径，禁止 `git add -A`/`-a`/`.`；提交前
  `git status --porcelain` 核对；提交后 `git for-each-ref refs/heads` 核对 7 条引用；
- 分支名不含斜杠；**不 push**、**不合并回主线**、不改已冻结契约（只追加）、
  不改写 `V1`–`V8`、不动 `.workbuddy/`、不修改他人地盘的代码。

**停止并上报的条件**（写状态板「待协商事项」+ 告知我，然后等指令）：
1. 需要变更或新增冻结契约字段；
2. 需要改别人地盘的文件，或与线 B 的占用冲突；
3. 同一测试连续两次修复仍失败，或发现计划与代码现实矛盾；
4. 需要新依赖、真实密钥、外部服务或数据库不可用；
5. `V9`–`V11` 号段不够用，或需要阶段 9/10 的号段（阶段 8 交付后由你追加分配）；
6. 任何"想顺手做掉"的计划外改动——先登记，不要直接做。

**阶段退出条件**：R1 链路真实跑通"已发布证据 → 索引 → 过滤检索 → 模型/降级 →
服务端引用校验 → 回答卡"，关键拒答/权限/时态/伪造引用/注入测试全通过，
产出首份可复核基线报告与证据账本；然后停下等我验收，**不得自行宣布阶段完成**
或调整后续阶段号段以外的计划。

## 二、给线 B（工具 + 编排 + 体验）

从现在起按分工表连续开发，直到本节任务清单全部完成，不必每步等我确认。

**循环**：与线 A 相同（快进主线 → 读档 → 取下一任务 → RED → 最小实现 → GREEN →
回归 → 小步提交 → 更新状态板）。任务顺序：
1. **会话持久化 JDBC**（进行中，`V12`）：存储实现 + 迁移 + 数据库契约测试；
   切换挂显式开关（如 `zhku.conversation.store=jdbc`，默认仍为内存实现），
   首个交付**不含**配置切换，切换单独小步；
2. **校园工具集 + Function Calling**：新包 `knowledge/.../tools/`，首批全部只读或纯计算
   （学分计算、选课冲突检测、毕业学分进度、校历/课表查询）；
3. **工具接入编排**：只提供 `tools/` 与工具注册接口，由线 A 的编排器经接口调用；
   **不改编排器文件**（见状态板职责重叠条，等你确认的边界即此）；
4. **SSE 流式输出**：使用已冻结的 `zhku.streaming.*` 配置键；
5. **答案卡升级（后端侧）**：前端 UI 由 WB-1 负责，不要改 `agent/frontend/`。

**硬性边界**：迁移用 `V12`–`V14`；改共享文件（含 `ZhkuLocalPreviewConfiguration`、
`knowledge/pom.xml`）前先在状态板登记；git 纪律与线 A 相同（只 stage 自己路径、
porcelain 核对、refs 核对、不 push、不合并主线、分支名不含斜杠）。

**停止并上报的条件**：与线 A 的 1–6 条相同（把"线 B"与"线 A"互换），
另外增加一条：任何需要动前端文件（`agent/frontend/`）的需求，先登记并上报，
由 WB-1 处理。

**任务退出条件**：每项交付有正常/边界测试与证据，`zhku.conversation.*` /
`zhku.streaming.*` 配置键与冻结契约一致；全部完成后停下等我验收。

## 三、通用纪律（两边都适用）

- 证据优先：没有测试和证据账本的"已完成"，一律视为未完成；
- 数字诚实：没有分母与基线，不给收益数字；不得称生产上线；
- 冲突不自行决断：地盘冲突、契约冲突、号段冲突 → 写状态板 + 上报；
- 每轮结束状态板必更新（四个时刻：开工 / 收工 / 合并前 / 合并后）；
- 里程碑不是自己宣布的，是我验收后由状态板记录的。
