# ZhkuAgent 本地提交流程

用户于2026-10-13确认采用：明确结果 → 验收通过 → 核对暂存差异 → 本地提交 → 记录SHA → 下一任务。本规则适用于当前T00—T10计划及后续开发任务。

1. 开始前记录分支、HEAD、暂存区和任务范围。保留用户既有改动；已有linked worktree可继续使用。暂存区存在不属于任务的内容时先核对，不覆盖或擅自取消暂存。
2. 完成一个可观察结果，运行适当的局部/流程验收，保存输入、结果、源码身份、失败记录、未验证范围及资源退出证据。到时限仍未通过，保存卡点，不进入下一任务，不把未完成实现记成已完成。
3. 按明确清单暂存实现、必要测试/依赖、规则和最小可复核证据。排除凭证、数据库、整本PDF、构建输出、缓存、临时恢复zip及无关学习/职业资料。资料仅用于已批准的本机受控范围，本地提交不授予公开上传许可。
4. 自审暂存差异：文件范围、依赖完整性、秘密检查、空白检查及暂存内容与已验收源码一致性。禁止无范围的全仓库暂存；审核快照与回执不得为凑验收而改写。
5. 创建本地提交，标题和正文说明具体变化、验证及限制。禁止把替身/回放通过写成在线模型或产品成功。提交失败时保留工作区和可核查记录，不自动重置、清理或改写历史。
6. 提交后确认HEAD、父提交、文件清单及选定文件无遗漏；保存实际SHA、树身份和验收证据路径。必要时另用一个文档提交保存主实现提交的回执，该文档提交自身身份从Git日志和最终答复查询，避免为写入自身SHA无限追加提交。
7. 本任务的本地提交成功后再进入下一任务。用户已授权该流程，不重复索取本地提交确认；push、PR、标签、部署、共享历史改写仍需对应授权。

当前历史工作区第一次保存采用一个T00—T03工程检查点，不倒推伪造四个阶段提交。后续按任务的独立可验收结果提交；确有依赖缺口时补必要依赖并说明，不吸收无关工作。

源码检查点的恢复以实际Git提交和外部资产清单为准。原PDF、运行凭证和本机依赖不会随Git恢复；在适用的专用临时库重新核对配置和运行，不操作原演示库。
