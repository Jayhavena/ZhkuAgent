# ZhkuAgent 统一集成与最终收口实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 按任务执行；用户未要求并行工作，本计划不派生子代理。每项以实际退出证据更新复选框，不以文件已存在代替完成。

**Goal:** 把已形成的规则查证 Agent 分支成果整合为同版本可演示候选，经在线质量和真实学生/PDF 对照后决定是否最终冻结。

**Architecture:** 沿用 knowledge 中独立规则 Agent 循环、证据工具/独立发布核验及现有共享 Runtime。先整合现有 T05/T06 与学生入口，再验 HTTP、代理、浏览器全过程；不重做技术架构，不把旧回放接口装成在线任务接口。

**Tech Stack:** 现有 Java 21、Maven 多模块、Spring/JDBC/PostgreSQL、Vue/Node 与本机 Nginx；不新增框架或升级依赖作为前置条件。

**Spec:** [2026-10-13 原任务合同](2026-10-13-rule-check-agent-plan-review.md)、[当前项目事实](../../zhkuagent/2026-10-18-project-status.md)、[本次固定身份清单](../../evidence/project-status/2026-10-18/source-audit.json)。T00—T10 及五个工作包编号保留；本计划只更新后续执行顺序，不重置旧失败或降低既定门槛。

## 全局约束

- 本计划更新本身已获用户授权；以下业务实现、集成及正式试验尚未在本轮执行。
- 主线起点 `804399f`；T00—T04 基础成果和 T07 功能已进入主线。T05/T06 后续、T08—T10 准备分支未合入。
- 资料仍限 2025.9.2 已审核历史文本与受控本机用途；不推断现行性、真实修读记录或个人资格。
- 每次数据库/供应商操作前重新按 Process→User→Machine 检查所需凭证并注入子进程，不打印值。写入只在专用一次性临时库，不写原演示库。
- 所有旧调用额度已关闭；真实外发先形成完整可审请求包并取得相应新许可。模拟/回放可独立验收，但不计在线通过。
- 普通用户终端按项目既有 `.cmd` 包装器和 PS5.1 中文边界验收，不假定用户 PATH 有 `pwsh`；只清理本任务自有资源。

## 重点复核的失败场景

1. 同步回放后端配异步任务页面：由任务一验证三种构建模式与 capabilities/实际接口一致，页面可达不能代替成功提交。
2. 新模型协议/事实目录与旧 HTTP 工厂装配混用：由任务一验证 T05 新侧、T06 显式装配、审核资产与合同身份，无隐式回放兜底。
3. 换身份、并发续答或取消后迟到结果复活：由任务一验证真实身份仓储、同任务/版本及两个浏览器窗口，保留资源退出回执。
4. 有依据却拒答被计为成功，或只统计成功调用：由任务二逐题评分、保留所有尝试和未知用量，关键错误不能平均抵消。
5. PDF 对照的记忆顺序偏差及失败样本被删除：由任务三固定配对/顺序/计时上限，并将失败、放弃和中断纳入记录。
