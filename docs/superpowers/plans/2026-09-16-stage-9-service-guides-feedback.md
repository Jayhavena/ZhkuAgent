# 阶段 9：办事清单、人工渠道与匿名反馈实施计划

> 状态：待执行；依赖阶段 8 统一回答卡和证据边界。

## 目标与非目标

将“知道规则”扩展为“知道下一步怎么做”：首批仅覆盖选课调整相关清单，展示已审核的材料、步骤、官方渠道和风险提示。系统仍不代办、不认定资格、不自动修改规则。反馈仅允许匿名结构化枚举，不能包含自由文本或个人信息。

   > 号段说明（2026-09-20 **已裁决，此为最终号段**）：本阶段的迁移按归属拆成两支——
   > **`V15`＝线 A（WB-3）**：`service_guide`、步骤、材料、官方渠道、风险提示、关联规则/通知版本；

3. [ ] 扩展统一回答卡：结论后可附“下一步”“需确认事项”“官方人工渠道”；高风险/不足证据时只保留人工渠道和风险提示，不能伪装成可办结方案。

5. [ ] 完成本地管理员最小审核界面/API与操作手册；学生侧只发送受限枚举，如“来源不清楚”“已过期”“未解决”“渠道不可用”。
6. [ ] 新增办事清单与反馈证据账本，陈述当前是本地匿名反馈闭环而非真实工单或人工服务平台。

## 先写的测试

- `ServiceGuideModelTest`：步骤顺序、渠道/来源必填、材料与风险约束。
- `ServiceGuideResolverTest`：有效通知/规则时返回清单；过期、替代、权限不足、资格待确认时只转人工。
- `HumanHandoffRouteTest`：证据冲突、个案认定、规则缺失、模型拒答均进入正确人工渠道。
- `AnonymousFeedbackContractTest`：接口拒绝自由文本/PII 字段，匿名散列不回传，重复反馈去重。
- `FeedbackRetentionTest`：Clock 到达 90 天边界时删除/聚合；管理员仅见聚合，反馈不能自动创建发布资料或索引任务。
- `ServiceGuideAcceptanceTest`：一条选课调整链路从回答卡到官方渠道可人工验收。

## 验收与退出条件

首批清单有正式来源、正常/转人工用例自动化测试和人工验收；数据库中无法写入自由文本或身份字段；到期清理可由受控 Clock 验证；证据账本完成。之后才能开始阶段 10。

## 不得提前做

- 不接真实工单、短信、邮箱、校务系统或学生身份；
- 不收集原始问题/回答以“方便改进”；
- 不让模型自己编办事步骤或官方渠道；
- 不让反馈自动调整检索排序、提示词、制度结论或资料发布状态。
