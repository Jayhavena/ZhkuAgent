## Global Constraints

- 目标用户是查阅校园规则的学生，首期围绕教务规则；资料维护者负责供给与纠错。先覆盖公开、获准传播、经过审核的资料。
- 核心成功标准：用户能够基于适用于当前情境的证据，正确理解规则、核对原文，并明确仍然未知的部分。
- 部分回答以独立成立的主张为单位；缺少会改变整体结论的条件/例外时先澄清或说明缺证/冲突，不用免责声明掩盖缺口。
- 不从虚构课程获得个人修读资格判断或实际办理能力；渠道指引不写“已受理”。
- 不把 Session 恢复当完整聊天历史，不自动续跑未知任务，不增加学分任务与重修 Session 的强制关联。
- 保留 3C 已验收的提交幂等、身份隔离、预算、停止与归档边界；不重写公共 runtime 或两条独立工具循环。
- 不做全仓改名、先迁目录、直接微服务化或引入 Redis/Kafka/独立向量数据库。P2 项必须有触发证据。
- 保留 Flyway 历史，采用新迁移；执行前检查当前最高版本，不能预占或重用迁移编号。
- 数据库写验收只使用专用临时库，禁止原演示库端口 54329、原数据卷及生产连接。数据库测试必须显式指定隔离目标。
- 每次数据库/DashScope 操作重新按 Process→User→Machine 检查所需变量；不打印密钥，不把密钥写入参数或证据。
- 普通用户终端验证独立于 Codex PATH；复用启动器及工具解析；中文兼容覆盖 Windows PowerShell 5.1 的 UTF-8 会话边界，不改全局配置。
- 中文注释只解释业务边界、状态约束与风险，并随实现同步更新。
- 保留已有 dirty 工作区；只记录/修改本任务白名单。禁止 reset/clean、批量提交已有改动、覆写旧报告。
- 路线图制定时仅规划；当前执行范围由用户授权与阶段实施计划限定。执行仍按阶段门禁推进，不把本文件理解成自动批准部署、破坏性操作或所有 P2 扩张。

## Review Focus

1. 数字正确但年级/课程类别错误：R5 的范围与条件用例必须拒绝误用，不能只校验数字集合。
2. 旧规定在检索后、输出前被撤回：R5/R6 必须阻断输出或重新取证，历史再展示同样核对。
3. 原文带脚本、提示注入或跨页例外：R2 原文安全渲染，R5 证据只作为数据，R6 不丢跨页条件。
4. 前端刷新、换账号、丢响应：R5 保留 3C 契约，不能自动重复提交、恢复旧身份正文或把未知视为未受理。
5. 手册只审一个章节但发布操作归档整个范围：R6 使用显式条款集合，拒绝隐式整范围替换。

## 1. 为什么这次值得做：三个可证伪假设

| 假设 | 预期收益，不是已有成果 | 证明方法 | 不成立时如何处理 |
| --- | --- | --- | --- |
| H1：适用范围、澄清和原文定位能降低查证成本 | 用户少翻文档，且不误用规则 | 单主题流程与官网/PDF 匹配难度任务对照 | 改问题分类/入口或保留搜索产品，不继续扩大资料范围 |
| H2：治理与证据协议比自由回答更可靠 | 数字、对象、例外、时效错误减少 | 同资料、同问题、同模型的抽取/模板与受限生成对照；人工依据原文判定 | 收紧到原文摘录/已审核模板，暂停自由解释 |
| H3：现有技术栈足够完成第一版 | 减少重写成本与新增故障 | 同环境的基线与新路径回归、查询计划、延迟、外发次数 | 定位具体瓶颈；没有瓶颈不迁框架、不加设施 |

核心交付不是“架构更漂亮”，而是：**同类问题更容易查证；有依据的回答更完整；资料错误能修订复验；现有可靠性不退步。** 文件数、框架数、模型自评分、总测试数增长不作为成功指标。

## 5. 怎么判断走在正确轨道：量化门禁

所有门槛均为**建议初始验收标准**，不是已有成绩。R0 可结合实际资料/环境调整一次并登记理由；看到留出结果后不得降低标准，改变标准需新决策与新留出。

质量集、已知风险集、裁判验证集分别报告。15/16、46/48是当前样本的验收计数；0漏放是已知反例合同，不是总体风险为0。没有合格评分与可复核输出不能宣称质量通过；观测改善但统计设计不足时标 `INCONCLUSIVE_CHANGE`，可保留受限试验，不能宣传已证明提升。

| 指标 | 定义 | G2 单主题门禁 | G4 三主题门禁 |
| --- | --- | --- | --- |
| 严重错误 | 越权正文、已撤回证据被输出、错误关键数字/对象、虚构办理结果 | 已定义安全/语义反例 0 漏放 | 全部关键反例 0 漏放；发现一例阻止发布 |
| 正确任务完成 | 状态正确且原文/对象/条件/例外符合标注；正确澄清/拒答可完成 | 16 题留出至少 15 题正确 | 48 题留出至少 46 题正确；逐主题报告 |
| 支持条款 Recall@5 | 可回答题召回其必要支持/例外条款的比例，逐题再汇总 | ≥90%，不低于最强简单基线 | ≥95%，报告两路与融合增益 |
| 主张支撑率 | 原子实质主张中人工判定被证据支持的比例 | 摘录/模板事实 100%；关键错误 0 | 摘录/模板事实 100%；若增加自由解释，人工支撑率 ≥98%且关键错误 0 |
| 不当拒答 | 可回答题错误拒答的比例，防止全拒答刷安全 | ≤10% | ≤5% |
| 原文定位 | 点击后到达对应实际段落、页码/条款与版本 | 全部引用 fixture 100%；真实样本全部可定位 | 所有验收引用 100%，撤回后阻断 |
| 部分回答与澄清 | 独立已确认事实有据，未知项明确；追问确实影响判断 | 全部既定边界案例通过；不暗示个人资格，不无关/重复追问 | 保持边界回归，报告各状态正确率和追问轮数 |
| 用户查证时间 | 仅正确完成任务的时间中位数，同时公开失败/超时 | 5–8 位目标用户、匹配难度且顺序平衡；不降正确率，时间减少 ≥20% | 扩样重复，仍不降正确率；同方向改善 |
| 本地检索性能 | 固定环境、10,000 条、并发 10、不含模型外发的 P95 | 记录基线，不先为优化迁设施 | 初始目标 ≤500ms；达不到先分析，不降低过滤/正确性 |
| 端到端生成 | 固定模型/参数、并发 2、成功/失败同时报告 | 记录 P50/P95、超时与用量 | 初始 P95≤10s；普通解释生成每次成功查询≤1次，embedding 外发另计 |
| 审核效率 | 同难度条款的有效审核耗时；漏条款和修订错误同时计 | 记录旧流程；不作为 G2 扩张前提 | 中位耗时减少 ≥30%，所有发布条款明确审核、0 关键漏项 |
| 兼容可靠性 | 与改动相关的 3C 身份/幂等/停止/历史门禁 | 所有必需类通过，无跳过/漂移 | 必需门禁全部通过；原受控 v1 行为不退步 |
| 评分可信度 | 人工参考、rubric版本、评分覆盖/未知；若用裁判则报告漏放与误拦 | 人工核对；裁判只辅助 | 独立裁判校准或保持人工；不设通用κ阈值 |
| 版本改善证据 | 同题改善/退步计数、差值区间、分组与检测能力 | 方向性报告；样本不足明确不能确认 | 独立确认与适用范围；未检测到差异不称等效 |

用户测试使用匹配难度的 A/B 题组与平衡顺序，避免同题第二次熟悉造成虚假省时；原官网/PDF 作为对照，招募与真实参与记录由用户提供或明确安排，不由 Codex 虚构。5–8 人只是方向试验，不能代表全校。

费用记录必须包括已知外发数、供应商/model 标识、返回用量、错误及未知项；只有取得可信用量和价目依据才计算金额。用输出参数或调用次数推算“费用精确封顶”不合格。

### 每阶段的方向判定

- **继续有限试验：**评分有效、当前样本质量门禁通过，用户观察有改善方向；如区间/设计不足则写尚不能确认提升，复杂度仍须对应明确问题。
- **调整：**技术通过但用户无收益，先改主题选择/澄清/原文入口，暂停扩范围。
- **收缩：**搜索/模板与复杂生成效果相当，保留更简单路径，减少模型参与。
- **暂停：**无可审核来源、严重错误、未授权数据进入模型、原数据写风险或未解决兼容回归；完成其他独立事项，依赖事项不宣称完成。
- **停止扩张：**两轮针对性试验仍无改善，保留可用搜索和已有修复，记录否定证据。不要用第三次大重构替代方向验证。

## 7. 开发证据与问题关闭规则

每个任务绑定 RC 问题 ID，每次执行使用唯一 batch ID。详见 [证据规范与初始台账](../../evidence/rule-check-refactor/2026-10-07/README.md)。
