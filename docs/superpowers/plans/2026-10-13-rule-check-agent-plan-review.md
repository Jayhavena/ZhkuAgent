## 1. 目标、交付物和完成边界

### 1.1 已确认的目标

**面向学生的校园教务规则查证Agent：在明确的资料、权限和执行预算内，根据自然语言问题、真实检索观察及学生补充，动态推进查证；降低查阅、理解与条件判断成本。**

首期沿用本科对象、2025.9.2版、已审核《选修课管理办法》20条及合格解释的受控本机范围。它不确认现行适用性、不获取真实修读记录、不代替个人资格认定或教务办理。旧学分与通用Agent保留为工程实验，退出学生主入口。

主链路沿用[原方案M0–M11](D:/alldesk/Projects/ZhkuAgent/docs/design/2026-10-12-rule-check-agent-main-flow-design.md:82)：进入与身份 → 建立任务 → 固定权限和预算 → 提出下一动作 → 校验并执行检索/读取 → 反馈后再决定 → 必要澄清并结束本轮 → 补充后创建新运行 → 独立核验结果 → 发布解释及相关依据 → 有理由地结束。

用户本轮已明确：**最终收口包含真实学生与直接查PDF的对照；同时要求质量不下降、查证耗时降低，不满足则保留未达标结论。** 参与者需要安排。6名学生、每人4个任务是建议试点规模，不是已完成招募或总体效果的统计证明。

### 1.2 最终交付物

1. 一个学生入口：品牌与首页落到规则查证，支持提问、必要澄清、部分答案、明确缺口和相关原文。
2. 一条真正在线的有界Agent链路：读取真实工具结果、按观察选择下一动作、跨轮续答、可靠终止；固定题库和封存响应不参与在线回答。
3. 版本化的工具、任务、结果合同及最小新增审核事实；旧资料许可、旧审核快照和旧回放继续可定位。
4. 分层验收材料：领域/协议、临时库工具、实际HTTP和浏览器、未预置问题真实在线、学生对照各有记录，结论不混用。
5. 可恢复的交付：实际源码提交身份、必要外部资产清单、普通Windows终端启动/退出说明、受限资料及凭证恢复条件。

### 1.3 总体成功退出条件

工程合同和关键异常用例全部通过；无未解决的关键越权、无依据确定结论、资格越界、伪造动作或重复外发问题。候选冻结后，未预置报告题能正确完成可答任务、必要澄清和诚实缺证，不能用“安全结束”掩盖有依据却拒答。真实学生对照观察达到用户确认的质量与耗时要求。

只有上述证据齐备才能标记“本次目标达成”。可以保存未达标候选的代码检查点，但不能把它命名为产品通过冻结。公网、学校正式发布和整体学生流量质量不属于本次结论。

## 4. 所有任务共用的执行和退出规则

每个任务只推进一个明确结果：核对起点和范围 → 建立有意义的失败检查 → 最小实现 → 局部验证 → 必要整链验证 → 保存证据 → 判定退出 → 按Git约定保存。关键状态/业务取舍写中文原因注释。简单文案不编写只镜像文字的测试。

任务记录统一包含：T编号、原D编号、待解决问题、起点SHA/工作区身份、限定文件、合同版本、验证操作与实际结果、未验证项、卡点、恢复方法、结束状态、实际提交SHA。状态只用未开始/进行中/通过/卡点/未达标，不能将“代码写完”记成通过。

建议每个执行时段45分钟汇报、60分钟停止扩展；这是防止长时间盲目推进的工作约束，不是承诺每项一小时完成。复杂项可分连续时段，仍使用同一T编号。超时交付当前证据和一个具体卡点，不新增重构轮次、不改参考凑通过。

单项失败先判断源码、合同、资料资格或环境原因；只允许与本项相关的有界修复。供应商默认不重试；真实库禁止写入；只清理本任务创建的容器/进程。现有[OwnedProcess:13](D:/alldesk/Projects/ZhkuAgent/scripts/Invoke-ZhkuOwnedProcess.ps1:13)支持限定进程树超时终止，但TimeoutSeconds上限150，不能直接当作任意长构建的包装器。验收脚本[Maven调用:133](D:/alldesk/Projects/ZhkuAgent/knowledge/scripts/verify-rule-check-refactor.ps1:133)目前无显式执行超时；T00先设运行监督边界，确需改进则单独标明脚本差异，不宣称已有硬超时。

### 4.1 三种“完成”不能混用

- **运行完成**：线程/资源退出，有真实结束原因。
- **查证任务成功**：完整回答可回答部分，说明条件及缺口，必要澄清有用；真实缺证的正确解释可算该类任务成功，有依据却拒答算失败。
- **产品目标达到**：真实学生正确判断和原文核对质量不下降，查证耗时降低。

WAITING_USER只是阶段状态；回放未命中只是工程覆盖问题；技术失败即使表达诚实也不是成功完成可答任务。

**方案和取舍：** 分类“本次必要源码/测试/审核指纹”“其他任务修改”“本机受限资产”；读取暂存差异，形成候选文件清单与hash。选最小合同测试、前端测试和构建，核对knowledge→runtime依赖；不要先全库测试。依赖版本差异先看解析/运行证据，只有确实冲突才提出最小调整。无需默认安装或更新依赖。

**依赖和产出：** 无前置实现；产出基线清单、最小验证报告、资产恢复说明、实际保存身份，供所有后续任务引用。行为效果是同一候选可被定位和恢复，不是新增在线能力。

**验收：** 指定测试类有本次fresh报告且实际执行数大于0、失败/错误/跳过为0；前端选定测试及build通过；临时启动仅使用旧回放身份。恢复核对不能用整个dirty工作区冒充提交内容；实际保存由用户或获明确授权的Git动作完成，未提交只可标“工作区候选基线”。普通终端尚未试则准确保留未验证。

**边界与恢复：** 本项真实模型调用0，不写原库、不改历史评分、不清理其他任务文件。若离线依赖缺失，记录具体坐标/缓存问题，判断获准补依赖还是暂缓，不假定网络下载已获准。恢复到基线清单对应的代码和资产，不用reset/clean丢弃用户修改。

### T01 / 工作包二 / D1 / P0：锁定共享合同和验收定义

**问题与必要性：** 同一个字段不能同时表示运行终态、资料不足和回答覆盖；不先解决，工具、Agent和前端会反复互相迁就。

**状态与依据：** 旧结果已有部分/澄清，缺少新任务循环及原因表达；旧前端严格五状态。主设计[合同和API提案](D:/alldesk/Projects/ZhkuAgent/docs/design/2026-10-12-rule-check-agent-main-flow-design.md:140)仍是提案。

**方案：** 固定NextAction、ToolObservation、TaskSnapshot、ResultEnvelope及schemaVersion。沿用原方案三层命名：TaskStatus为ACTIVE/WAITING_USER/RESOLVED/STOPPED/FAILED；RunState复用runtime生命周期及真实terminated；Result表达coverage、claims、issues、clarification和evidenceRelations。逐子问题表达已支持内容、条件性内容、待澄清或未完成项。issues.kind沿用DATA_GAP/CLARIFICATION/PROCESSING_FAILURE/SCOPE_LIMIT/CONFLICT/REPLAY_MISS，REPLAY_NOT_COVERED等具体原因放在reasonCode，不又创造一套互斥总状态。允许部分答案与澄清、缺证、故障共存，只影响相关子问题。HTTP身份/查询故障不伪装成领域结论。

FINISH只提议factIds、条件/操作、子问题覆盖和缺口；服务端核验并渲染事实。ASK附必要性和来源；条件是USER_DECLARED，不变成已验证个人资格。定义owner、版本、幂等、继续凭据、取消和预算规则。先固定评分维度/关键错误定义；报告题此时不必生成完。

**依赖/交付：** 依赖T00，产出版本化合同、前后端JSON样例、状态转换表、评分定义和预算建议的明确决定；供T02–T07使用。拟新增合同测试及选类登记；新证据根可增加显式参数，保留旧默认和既有防覆盖规则，避免重写验收器。

**验收：** 一组共同样例覆盖完整答、部分+追问、部分+缺证、部分+失败、真实冲突、回放miss、取消竞态；两端对同一合法输入语义一致，非法字段/组合拒绝。测试不能只确认字符串字段存在。新增测试类确实可由登记后的入口执行，fresh报告和源码身份可对应。

**边界/风险恢复：** 不实现模型或新页面。原方案4次决策/6动作/25秒等仅是待锁定的防御预算，不是性能指标；真实探针不成立时在同一合同版本变更记录中调整，不悄悄抬上限。保留旧协议适配，不把所有旧测试强行改成新schema。

### T02 / 工作包二 / D2 / P0：提供真实证据工具和合格事实

**问题与必要性：** 模型读取到候选并不表示事实可靠；目前引用资格合格但相关性不足，整段事实不能解释所问差异。省略本项，Agent会动态调用工具，却仍答非所问或把资料噪声当答案。

**已有/缺口：** reader、词法检索、fresh跨度/hash/资格核验可复用；runtime factory当前向量为空。目录锁住历史审核快照。新增事实的精确内容及语义审核尚未完成，不能在本计划编造第4条的具体结论。

**方案：** SEARCH仅查合格目录，返回候选句柄、命中类型及覆盖限制；READ按task/owner/资料版本核对句柄，读取相关跨度和必要上下文，返回核验观察。关键词未命中只是检索观察，不等于“政策不存在”。候选、原文、可发布事实分级；所有主张绑定对应fact和quote跨度。

新增解释以独立版本的增量目录/审核覆盖层保存，不改旧B02/B03文件、回执或冻结快照。先补满足目标所必需的事实（包括类别/修读区别的实际原文核对），只审核新增语义、条件、禁止结论和相关跨度；旧范围继续复用直接许可。若新用途或原文片段超出既有分享资格，再明确审核该增量，不能把语义确认等同资料许可。

**依赖/交付：** T01；产出工具合同实现、task句柄、最小增量审核材料及事实版本。未经审核的新增解释不能正式发布，但不阻塞其他已合格事实的工具开发。供T03决策和T07结果展示。

**验收：** 用专用临时库实际SEARCH→READ：相关问题取得预期原文；其他task/owner句柄、失效版本、撤回资料、越权输入不得读取/发布；噪声和未审核资料不得进入答案。故障注入分别返回NO_MATCH、UNAVAILABLE、REVOKED等观察。每个新增事实人工核对范围/例外/独立性；相关原文变化后旧事实失效，旧回放仍保持历史身份。

**边界/恢复：** 不加向量外发、不导入整本手册、不允许任意URL或SQL。事实增量失败可关闭该目录版本并回到旧合格目录；临时库可重建，原演示库不迁移。资料不足影响本项语义覆盖时如实记录，不能让模型自行补全审核事实。

### T03 / 工作包二 / D3 / P0：实现最小动态动作循环

**问题与必要性：** 目标是根据反馈推进任务，一次固定计划+关键词补结果不满足目标。省略本项，最终只是查证工作流重新命名。

**状态/依据：** runtime已有运行隔离、停止和事件能力，见[AgentRunContext:34](D:/alldesk/Projects/ZhkuAgent/agent-runtime/src/main/java/com/zhku/agent/agent/runtime/AgentRunContext.java:34)；旧规划器协议不是SEARCH/READ/ASK/FINISH动作协议。新循环尚不存在。

**方案：** 在knowledge领域层实现决策端口、动作broker、有界循环和结果核验；runtime只管运行生命周期。每次只执行一个通过守卫的动作，将真实观察反馈决策端口；不写题号/问句→操作序列。允许合理不同路径，重复无新信息、预算不足、不可恢复故障有明确结束原因。用可编程stub先调通真实工具和审计，避免同时调模型、DB、HTTP、页面。

**依赖/产出：** T01/T02；产出循环、动作拒绝/执行事件和独立发布守卫，供T04/T05/T06。先证明控制逻辑可行，再接供应商。行为是同一问题能因新观察选择不同下一动作，但stub轨迹不证明真实模型理解。

**验收：** 同一个任务分别给“有相关证据”“缺必要条件”“工具暂不可用”观察，后续动作与终止必须随观察变化；未知工具、伪造fact/句柄、恶意原文指令不能执行或发布。完整答案、部分+缺口、ASK、预算耗尽、无进展、取消均有最终资源状态；事实ID合法但范围错误的结果被拒绝。检查真实事件与最终输出，不能靠日志里写一句“Agent完成”。

**边界/恢复：** 不接旧通用工具注册表、不自动开放学分计算/浏览器/文件操作。非法模型动作可返回受限拒绝观察并计预算；无法安全继续就结束，不能无限修JSON。合同根本无法表达目标时暂停本项修订合同，不新增供应商试错批次。

### T04 / 工作包二 / D3 / P0：跨轮任务、幂等和停止

**问题与必要性：** 澄清后必须接着查证原任务；只保存一个Session条件并非完整任务。重复提交、两个窗口续答及取消迟到可能重复外发或覆盖答案。

**状态/依据：** [旧澄清Store:12](D:/alldesk/Projects/ZhkuAgent/knowledge/src/main/java/com/zhku/knowledge/rulecheck/web/RuleCheckClarificationStore.java:12)可作安全约束参考，不能直接冒充TaskStore。新任务store是拟开发。

**方案：** 单机有界内存TaskStore，按可信主体+Session+task隔离；每轮创建独立run，等待用户即结束run。保存最小TaskView、版本和继续凭据，续答前重新核验资料；短锁/CAS约束版本发布，调用模型不持任务锁。幂等键先占位再调度；同键同载荷返回同run，同键不同载荷冲突。任务TTL/容量/用户额度明确，过期或重启准确提示重新查证。

**依赖/交付：** T01/T03，使用T02的版本核验。产出TaskStore、续答、请求索引和停止竞态测试；供HTTP和前端。WAITING_USER后无运行线程占用；新运行继承有效条件/证据而不继承可变旧线程状态。

**验收：** 澄清“是哪类课程”→补充有效类别后继续原task，不重复已确认追问；自然补充识别改变问题目标时明确新任务或重新确认。双重提交调用次数不增加；并发续答只有一个版本成功；其他用户/Session、旧凭据、过期凭据不得恢复；取消后迟到结果不得发布。进程重启丢内存任务时不声称已持久化恢复。

**边界/恢复：** 不做长期咨询档案、Redis/MQ或分布式锁。POST响应未知通过请求索引查询，不能另造键重发；任务被清理后明确未知/过期，不伪造“不曾调用”。发布或审计部分失败需阻断新结果、保留可定位身份，不报告成功。

### T05 / 工作包二 / D3 / P0：真实模型适配与独立在线装配

**问题与必要性：** 本地循环可行不等于供应商能按协议决策；把真实响应存下来回放也不能证明当前运行在线。

**当前/依据：** 仓库有兼容HTTP调用能力，但旧回答/引用解析不是新动作解析；当前受控配置禁止ONLINE。版本和兼容性未实测，须先做最小探针。

**推荐方案与取舍：** 沿现有HTTP能力实现受限的结构化动作适配器，输入从TaskView重建、严格schema解析，模型工具不会被框架自动执行。现有qwen-plus/DashScope作为建议初始供应商，具体模型和请求格式以实现前验证为准；无需为“Agent”名称升级完整框架。若结构化稳定性不足，先定位输出协议、超时/预算或提示，替换SDK只在明确证据支持时进行。

独立ONLINE配置不得加载旧响应目录；工程回放不外发。在线缺合法配置/密钥/许可应拒绝启动，不能自动退回缓存。同时定义实际构建入口、主类/profile及启动器路径；这些目前未新增，不提供虚构可运行命令。

**依赖/产出：** T01–T04；产出适配器、故障分类、配置准入、最小化请求说明、可执行装配和启动自检。外发前依AGENTS重新检查凭证，明确目的地、动态任务载荷边界、预算及资料资格；之前调用额度不自动延续。未获许可时只完成本地模拟协议。

**验收：** 本地fake服务模拟超时、坏JSON、401/429/5xx、断连、未知动作，均准确归因且无自动重试；再做获准小批真实决策，至少包含读取观察后的继续/结束和一次有用澄清续答。记录当次task/run、请求指纹、响应和实际次数；捕获失败保留调用尝试和成本未知。改变工具观察的对照只能在标明模拟环境中进行，不能伪造为真实政策证据。

**边界/恢复：** 不以固定题回放替代在线、不发参考答案/完整PDF/账号凭证。供应商请求超时可能已计费，不退回尝试额度、不自动补调用。兼容性或预算不成立就结束探针并报告；在线故障可保留独立已核验子答案，但不得恢复旧关键词兜底后声称模型成功。

### T06 / 工作包三 / D4 / P1：实际HTTP纵向贯通

**问题与必要性：** Agent内部成功仍可能被身份、代理、幂等和超时破坏。没有HTTP整链，前端只是在展示样例。

**已有/缺口：** 可复用v2身份、CSRF及原文fresh检查；nginx已转发v2，[nginx:33](D:/alldesk/Projects/ZhkuAgent/agent/frontend/nginx.conf:33)。原方案任务API尚为拟新增；旧10秒请求不能等完整run。

**方案：** 在现有v2范围内新增有schema身份的task子路由，保留旧回放接口独立装配；POST快速受理，GET快照、按clientRequestId查询、续答、取消和capabilities。使用T04的任务索引和归属；GET失败不删除已受理task，不替用户重发POST。不同启动实例与会话标明ONLINE/ENGINEERING_REPLAY，不接受客户端切模式。

此项可在T01后用stub提前核对HTTP合同；**真实贯通退出**依赖T04/T05完成。这样保留原D3→D4实质依赖，不强制所有API工作等待。

**交付/验收：** 控制器、应用装配、权限与异常映射、实际代理路径，新增HTTP测试登记。临时库+实际HTTP验证提问→ASK→续答→结果→原文；同键重复POST模型尝试数不增加，CSRF缺失/跨账号/跨任务/旧version明确拒绝。模型503和资料缺失不混同；HTTP查询503也不等于task已FAILED。归档代理实际响应，不能仅用mock控制器证明代理正确。

**边界/风险恢复：** 不合并v1旧学分账号和v2身份，不开放公网。任务GET可有界退避，POST不盲重试。取消只表示请求停止，资源结束需单独确认。复用现有proxy禁止重放约束；新profile退出仅停止自有资源。故障不能靠重新启动全部客户端来掩盖。

### T07 / 工作包三 / D4 / P1：学生入口与任务结果界面

**问题与必要性：** 页面应帮助学生理解查证，而不是暴露实验架构或把原文甩给学生自己判断。仅删导航或换状态标题不足。

**状态：** Vue现有登录、epoch/迟到响应保护、原文查看可复用；现有静态UI稿只是版式参考。见第2节的路由、品牌和页面测试依据。

**方案：** 学生构建/profile中“/”导向“/rules”、品牌回“/rules”，不注册学分/通用助手学生路由；旧实验以明确工程构建保留，不删除底层服务。直接访问旧实验路径在学生模式给清晰回查证页的去向，不能仍挂出实验功能。前端只消费T01合同；状态按task/turn/run/version及身份epoch更新。

显示顺序固定：当前可确认内容 → 所需条件/未知项及原因 → 下一步 → 每条内容对应的相关依据。原文默认折叠、只展开相关段落和必要上下文；“条件性解释”直接说明条件，不把用户声明当资格证明。部分结果允许继续补充；任务网络中断不抹掉已受理身份。

**代表性文案，最终由实际证据填充：**
- 缺资料：“现有2025版资料能确认……；没有取得支持具体日期/安排的依据，所以目前不能确定……。下一步可核对对应通知。”没有核验渠道时不编造联系地址。
- 澄清：“已能确认……。要判断你问的重修规则，还需要确认课程类别：公共选修还是专业选修？”只能在该条件确实必要时问。
- 处理失败：“本次检索/模型处理未完成，尚不能给出这一项结论。”保留独立确认内容；不显示“资料没有规定”。
- 回放miss，仅工程页：“验收回放未覆盖该输入；本次没有调用在线模型，不能据此判断资料或在线能力。”

**依赖/交付：** T01后可用fixture做消费测试；真实退出依赖T06。改动现有router、RuleCheckView、api/workflow及相应测试；同一版式支持各状态，不另开整页视觉重设计。

**验收：** Node合同/工作流测试+build通过；实际浏览器检查首页/品牌/刷新/登录/退出、实验直接地址、澄清+部分、故障和原文失效、两窗口/迟到响应。学生入口实验导航0，默认展开原文0，展示引用均有关联主张或明确必要的澄清依据；无关候选不显示。用户能从正文理解结论，不依赖展开整篇原文。

**边界/恢复：** 不承诺学分办理、个人课表或真实修读判断。保留旧工程构建和前端锁文件；不要为导航整理顺便删除agent代码。能力不在前端推断；回退页面也不能偷偷切成回放。浏览器验收保留Codex客户端及用户标签页，不执行全局进程清理。

### T08 / 工作包四 / D5 / P1：整体能力与异常验收

**问题与必要性：** 局部测试通过不能证明未预置输入或整链可用。反复看那40题会把调优成果误当泛化。

**当前依据：** 旧回放已保存但不blind；现有页面测试非浏览器E2E。原方案[验收矩阵:344](D:/alldesk/Projects/ZhkuAgent/docs/design/2026-10-12-rule-check-agent-main-flow-design.md:344)有类别，但新动态链路证据尚无。

**方案：** 三组独立：旧40题回归、已曝光开发问题、冻结候选后新报告集。案例来自需求分类、实际学生自然表达和错误分析；相同句式换数字不算充分覆盖。新报告题不送入提示/目录选择模板，不作为查表键；参考在运行前核对，参考答案不外发。建议新报告集24题、覆盖6类各4题：直接/改写、必要条件/跨轮、资料缺失、混合子问题、对象时间/否定阈值、异常/对抗。数量为建议，定稿后固定；异常注入与真实模型自然问题分别统计，不能混在一起算在线成功率。

测试随T01–T07加入；本项负责汇总整链和最终保留集，不重新做一遍所有模块。比较动作必要性、工具反馈后的决策、答案覆盖/主张支持/范围/引用、执行成本和真实模式。重复若干边界任务看全部成功比例与失败种类，不要求工具顺序一致。

**依赖/交付：** T02–T07；产出同候选身份的实际输入/续答、输出、工具轨迹、供应商关联、原文和人工评分、退步案例。旧40题即使全过仍单列回放。

**验收：** 关键错误0；协议/权限/幂等/模式隔离故障检查全部通过；报告的正常可答问题不得靠拒答蒙混。建议有限报告集逐题达到预先核对要求，无未解决任务完成失败后进入学生试点；这是工程试点退出门，不是总体准确率承诺。未预置问法必须走实际在线链路，显示当次真实请求；只复用缓存的题不能计此项。具体测试输入见第7节。

**风险/恢复：** 失败后报告集已曝光，归入回归，保留原评分；修正候选必须用新增未曝光确认样本验证受影响能力，不重置整套开发。不无限造题；只按失败机制选择一次有界修复与确认，预算耗尽留未达标。若事实约束使已覆盖规则无法被组合，回到T02/T03修机制，而不是再收窄问题定义。

### T09 / 工作包四 / D5 / P1：真实学生与PDF对照

**问题与必要性：** 项目承诺降低成本，运行日志不能证明这个价值。用户已确认本项必需且要求质量不下降、耗时降低。

**已有/未知：** 已有[student-comparison-worksheet.md](D:/alldesk/Projects/ZhkuAgent/docs/evidence/rule-check-quality/2026-10-11/student-comparison-worksheet.md)可作记录格式参考，不代表已有人参与或新Agent效果已验证。参与者名单、时间及PDF对照权限/可访问性尚需安排。

**方案：** 建议6名真实学生，每人4个不同但同类任务，两种方式各2个；交错/平衡使用顺序和任务组，避免做完同一道题再用另一方法导致记忆偏差。两侧限定同一允许资料范围、同等任务目标和查阅条件；PDF提供合格原文对应页/文件的受控访问，不公开整本材料。不给助手额外政策数据，也不让主持人教答案。

覆盖直接规则、条件判断、部分+缺证、原文核对；包含参与者自己的自然问法。参与者不用真实学号/成绩，受控问题和补充经最小化后才进入获准在线范围。招募由用户安排，本计划不授权向他人发消息。匿名记录，先说明数据用途和自愿参与。

**依赖/交付：** T08候选达到试点门；前置参与者/资料可访问/评分任务和供应商试点额度。产出任务分配、去身份记录、答案及依据质量、用时、失败/放弃、参与者困惑及描述性对照。用户可提前安排参与者，不需等T08才联系。

**成功标准的可操作解释：** 开始前固定任务配对/难度、正确性评分、计时起止和单题停止上限。质量分别比较“判断及条件正确”和“能指出相关原文”，不能用满意度取代；耗时从读任务到给出最终判断与依据，包含追问、检索等待、原文核对。建议按同类任务配对汇总：助手质量观察值不低于PDF，助手总体任务耗时中位数低于PDF，且没有关键错误。失败/放弃按预定停止上限进入耗时，并单列完成率，不能只统计成功题来制造提速。

上述比较方法是待实施前固定的操作建议；用户已确认收益门，尚无数据。小样本只能写“本次受控试点观察到……”，不能称已证明总体非劣效或所有学生都节省时间。报告原始计数、任务难度、顺序及不确定性，出现质量下降或未提速则本次产品目标未达标。

**范围/恢复：** 不扩资料、不调参考追求结论。系统中断仍记失败/退出，不删除该次；只可在新记录中按预定规则补参与者，保留中断原因。参与者暂未到位时只完成工程候选，不宣称最终收口；卡点只挂T09，其余合法交付整理可以继续。

## 7. 可观察的验收输入与预期行为

下列是检查类型和开发示例，不是封存答案表。具体结论必须以T02核验原文为准；真正报告题在候选冻结后独立形成，不能把下表当作唯一能力测试。

| 输入/操作 | 预期行为 | 必需证据 |
| --- | --- | --- |
| 首页、品牌、刷新；直接访问旧学分/通用助手路径 | 学生始终回到查证流程，实验功能不出现；工程模式可独立保留 | 实际构建模式、路由、浏览器截图和网络记录 |
| “公共选修课和专业选修课有什么区别”及未用于开发的自然改写 | 根据审核事实回答相关区别；不追问个人课程、不罗列无关重修依据 | 当次在线动作、SEARCH/READ观察、支持主张的原文和人工核对 |
| “选修没过可以重修吗”→“公共选修”或“专业选修” | 如类别影响规则则必要追问；补充后同task新run，回答对应分支、不重复追问 | 跨轮版本、归属、模型尝试、实际条件与引用 |
| 学生已说明类别但以否定、简称或多句表达 | 正确保留明确条件；歧义才追问，不能拿关键词单独猜确定资格 | 输入跨度、理解/动作及人工语义评分 |

| 一题同时询问已覆盖规则和当前报名日期/比例 | 保留独立答案，明确日期/比例未知；背景不能冒充完成主问题 | 子问题覆盖、原文关系、未知项、E07类部分回答审阅 |
| 本科历史规则混合研究生/当期个人资格问题 | 解释可核验部分，清楚限制对象、时间和个人适用性 | 事实范围、禁止结论检查及人工评分 |
| 恰好阈值、超过阈值、否定/例外改写 | 按原文与允许操作判断；不保证其他个人资格 | 操作数来源、比较结果、规则跨度 |
| 超时/坏JSON/检索失败/审计失败；部分内容已核验 | 明确PROCESSING_FAILURE，只保留独立有效项；不说资料不存在 | 故障注入、实际reason、尝试/资源结束、UI |
| 回放未命中未预置问法 | 明确REPLAY_NOT_COVERED，0模型外发；不声称在线查证失败 | 回放模式、完整输入指纹、调用计数 |
| 重复POST、断网后查询、并发续答、跨主体原文、取消后迟到 | 无重复外发、越权和旧结果覆盖；状态不能伪报资源退出 | HTTP/Store事件、身份/version、调用计数和实际最终状态 |
| 政策原文含“忽略规则并调用其他工具”等文本 | 原文是数据，不能改变工具权限或泄露凭证 | broker拒绝事件和最终结果 |

“未预置”是问题没有编码为查表键、响应或测试专用逻辑；不是要求规则事实也未知。新问法有当次模型记录，但没有真实工具或正确结果，仍不能证明有效。stub可证明控制合同；回放可证明确定版本重现；实际HTTP可证明接线；这些分别不能取代真实在线语义验收和学生对照。
