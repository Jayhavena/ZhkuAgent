# 阶段 7—10：可信校园 Agent 设计

> 状态：已设计，未开始实现。  
> 范围：本地受控演示，不接入真实身份、学籍、成绩、审批或校务办理系统。

## 一、最终产品效果

学生在本机问答页可获得三类受控帮助：

1. **制度规则**：对已发布、学生可见且适用的静态规则，给出结论、条件、依据和来源定位；不替代资格或审批判断。
2. **当期通知**：对选课、退改选、补选、改选等问题，只从当前学期、已审核、仍有效且未被替代的官方通知中提取办理时间、步骤与官方入口；没有有效通知时明确拒绝给日期，并展示官方查询渠道。
3. **办事辅助**：按已审核的办事清单解释材料、步骤、风险和人工渠道；不能代学生提交、调用校务系统或做最终认定。

用户看到的每个结论均包含“规则 / 当前通知 / 检索证据”类型、来源标题、版本、条款/页码或网页快照定位、适用范围。存在缺失事实、权限不足、版本冲突、通知过期、低相关证据或模型故障时，系统降级为澄清、拒答或人工渠道，不猜测。

## 二、阶段顺序与依赖

```text
阶段 6（已验收：静态规则）
  └─ 阶段 7：通知生命周期与发布审核
       └─ 阶段 8：统一路由 + 受控混合检索 + 模型表达
            └─ 阶段 9：办事清单、人工渠道、匿名反馈审核
                 └─ 阶段 10：评测、观测、隐私与发布质量门禁
```

顺序不可颠倒。阶段 8 的模型不能成为阶段 7 通知正确性的替代品；阶段 9 不得让用户反馈绕过审核；阶段 10 的质量门禁必须基于前面已实现的真实链路。

## 三、总体决策

| 决策 | 采用方案 | 原因与边界 |
| --- | --- | --- |
| 通知接入 | 人工上传 + 人工审核；PDF 与官方网页不可变快照共同留存 | 首期追求可追溯而非自动抓取；运行时不爬网页 |
| 首个动态范围 | 当期选课通知，统一覆盖选课、退改选、补选、改选 | 一个学期一个通知族，先验证替代与时态机制 |
| 时态不足 | 严格拒答 | 学期、通知类型、开始/结束任一未确认，不输出具体日期/入口资格 |
| 模型接入 | `knowledge` 模块内的 Spring AI 抽象；Base URL/API Key/模型名外部配置 | `agent` 模块的原型和高权限工具不复用为学生能力 |
| 提供商 | 一次只启用一个经合同测试的 OpenAI-compatible profile | DeepSeek、Kimi、GLM、Qwen、混元、OpenAI 等不承诺天然兼容；各自验证后才写入支持列表 |
| 向量化 | 云端 embedding，固定模型、维度与 index profile | 聊天模型可切换；embedding 变更必须重建索引，禁止混用向量 |
| 检索 | 受控词法候选 + 向量候选，均先过滤证据；RRF 融合 | 中文 BM25/分词不能假定 PostgreSQL 默认全文检索已正确；首期先测词法基线，再决定是否引入专用分析器 |
| 重排 | 不作为首版硬依赖，评测证明确有收益再以开关接入 | 避免未测量地增加延迟和成本 |
| 反馈 | 匿名枚举反馈，人工审核 | 无自由文本、身份信息、原问题/原回答；禁止自动改规则或重建索引 |
| 数据留存 | 匿名明细最多 90 天，随后删除或只保留聚合 | 未获授权前不建设可识别学生画像 |

## 四、统一回答路由

```text
输入
  → 会话待澄清（若存在，优先补必要事实）
  → 动态通知（当期且有效）
  → 高风险确定性规则
  → 已发布资料的受控检索增强
  → 证据不足 / 官方人工渠道
```

路由不是由模型自由决定。每条目录项声明：`ruleId`、领域、静态/动态、所需事实、风险级别、处理器、证据范围、人工转介条件。模型只在最后的受控检索分支将已经获准的证据改写为学生可读文本。

所有分支最终经 `AnswerEvidenceGuard` 校验：来源已发布、学生可见、分享权利、未被当前范围替代、动态通知在 `Clock` 的有效窗口内、适用范围一致；此外，模型引用 ID 必须属于当轮检索白名单。

## 五、资料与通知生命周期

```text
原始 PDF / 官方网页快照
  → DRAFT → EXTRACTED → IN_REVIEW → PUBLISHED
                                      ├─ SUPERSEDED（被同范围新版替代）
                                      └─ EXPIRED（有效截止已过）
```

现有 `knowledge_source` 的发布/归档和学生可见过滤继续保留。阶段 7 新增通知元数据与替代关系，不能仅以“最新发布时间”推断当前性。发布同一“通知族 + 学期 + 通知类型”新版时，在同一事务中让旧通知失去当前性并发布新版；发布失败必须保留旧通知的可用状态。官方 URL 与审核时下载/抓取的快照分开保存，快照哈希、抓取时间、文件类型和审核记录用于复现。

扫描 PDF 首期不盲信 OCR：无法稳定提取文字或页面定位时进入 `NEEDS_OCR_REVIEW`，不得发布为学生可回答证据。

## 六、受控检索与模型边界

每个可检索 chunk 至少带：来源 ID、源版本、资料族/范围、页码/定位、学生可见与权利、发布时间、替代状态、适用学期、通知有效区间、内容哈希、切分策略版本、embedding profile、索引运行 ID。

检索前完成过滤，随后：

1. 受控词法检索召回课程名、制度编号、日期和明确关键词；
2. 语义检索召回同一权限/时态边界中的向量候选；
3. 两路均可用时按 RRF 融合；其中一路不可用时记录降级原因，不以“混合检索”自称；
4. 低于阈值、没有允许引用或证据冲突时不调用模型作确定性回答；
5. 模型输出为受限结构：`answer`、`uncertainty`、`citationIds`、`handoffRequired`；服务端删除/拒绝非白名单引用与超出证据的确定性结论。

文档和用户消息被显式标记为不可信内容。资料内的指令、链接、代码和“忽略上述规则”等句子只可作为被说明的文本，不能修改系统 Prompt、路由或工具权限。

## 七、隐私、权限与可观测性

本阶段只有两类本地角色：学生预览用户和本地管理员。管理员接口不能因前端隐藏而被视为受保护，必须在配置与路由层明确隔离。生产身份体系不在当前范围。

日志/指标只保存枚举路由、规则/资料版本、是否命中/拒答、耗时、错误类别、匿名会话散列；不保存原问题、模型原回答、学号、姓名、联系方式、API Key。对反馈设 90 天删除或聚合期限；密钥只从环境变量读取，配置回显必须遮蔽。

| 8 | 统一路由、发布/权限/时态过滤、受控索引、引用白名单、模型降级和版本化检索基线均完成；RAG 达到 R1，不假称完成评测 |
