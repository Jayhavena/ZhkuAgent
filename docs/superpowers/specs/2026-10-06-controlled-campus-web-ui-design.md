# 受控校园网页视觉与密码交互方案

状态：设计建议，2026-10-06。用户已明确要求页面更美观、密码可以隐藏/显示。本轮不实现Vue页面；布局和颜色是推荐默认方案，可以在首张页面预览时调整，不再扩展业务范围。

## 目标与推荐方向

为实习求职展示做一个清晰、整洁的校园事务工作台。主任务是填写合成课程、理解运行状态、查看带出处结果，并在本人历史和重修澄清之间切换。当前页面只有通用演示入口，校园页面是后续新接线；不靠修改首页标题宣称业务已完成。

采用浅色工作区＋深蓝导航＋青色主操作。突出课程数据和政策出处，避免占屏宣传、虚构统计、炫光和持续动画。技术诊断留在可展开区域，不把Runtime枚举、日志和预算当主界面内容。

对比：保留现有通用聊天布局改动少，但不利于呈现课程表、归档与出处；深色技术控制台有展示感，但不适合阅读政策与填表。推荐校园事务工作台，使已有工程语义更容易被用户理解。

## 统一视觉规则

| 项目 | 推荐约束 |
| --- | --- |
| 主背景 | #F5F8FA，浅灰蓝；内容面为#FFFFFF |
| 主色 | #173B59，深蓝；用于导航、标题和品牌 |
| 强调色 | #087F8C，青色；用于主要操作和选中态 |
| 正文/次要文字 | #172C3D / #526575，不用过浅文字表达重要信息 |
| 字体 | 优先本机中文无衬线Microsoft YaHei、PingFang SC；不加载外部字体 |
| 字号 | 页面标题28px、段标题18px、正文15～16px、次要信息13～14px |
| 间距 | 8px基础节奏，内容区24～32px留白；正文行高约1.6 |
| 边界 | 分区线、表格行和少量8～12px圆角；不用每段都装进相同卡片 |
| 状态 | 绿色完成、琥珀色待确认/隐藏、红色失败；始终配文字，不能只靠颜色 |
| 动效 | 仅用户操作反馈和有事实支持的加载；遵守减少动效偏好 |

## 页面安排

### 登录

桌面左右分区：左侧为项目名称、用途与“本机合成演示”标识，右侧为短登录表单。移动端只保留简洁单列表单。无注册、找回密码、记住密码或自动角色切换。

```text
┌──────────────────────────┬─────────────────────┐
│ 仲园 Agent               │ 登录校园工作台       │
│ 校园政策与学分任务        │ 账号 [              ]│
│                          │ 密码 [          眼睛]│
│ 学分核验 / 出处 / 历史    │ [登录]               │
│ 本机合成演示              │ 登录错误/操作提示     │
└──────────────────────────┴─────────────────────┘
```

### 学分任务

顶部显示项目名、当前账号和退出；左侧导航为“学分任务 / 我的历史 / 重修咨询”。主区展示课程表格与提交操作，下方是实际运行状态；右侧展示确认结果和政策出处。小屏按课程→状态→结果→出处顺序堆叠。

```text
┌────────────────────────────── 当前账号  退出 ──┐
│ 导航       │ 学分任务                          │
│ 学分任务   │ 填写虚构课程           结果与出处   │
│ 我的历史   │ 课程编号 / 类别 / 学分  合计学分    │
│ 重修咨询   │ [添加课程]             政策结论    │
│            │ [填入演示课程] [提交]  来源与范围   │
│            │ 运行状态 / 取消请求    人工核实提示 │
└───────────────────────────────────────────────┘
```

结果区不是无条件显示的固定成功样例。未运行显示操作指引；取消请求、正文隐藏、归档未确认和错误均有对应内容，不让旧答案留在背景。来源展示名称、版本、定位及适用范围；API没有可访问URL时不伪造链接。

### 我的历史

优先可扫描列表，显示任务摘要、执行状态、归档状态和时间；详情展开确认结果与出处。空列表提供“创建学分任务”。没有总量API则不显示虚构累计任务数；按现有cursor翻页，不伪造页码/总页数。

### 重修咨询

采用简洁问答区＋状态提示，明确当前还需要什么信息。显示取消、过期和冲突提示。刷新/重启后只提示“已恢复待澄清状态”，不补造历史聊天气泡。

## 密码显示与隐藏：必须实现

1. 首次进入默认隐藏；右侧眼睛按钮在“显示密码 / 隐藏密码”间切换，可反复操作。
2. 切换不改密码值，不提交表单；保存输入光标/选择位置，尽量保持当前输入体验，键盘焦点不得丢失。
3. 按钮支持Tab与Enter/空格，使用真实button，明确非提交类型；有当前动作名称与显示状态，图标本身不承担唯一说明。
4. 允许粘贴和浏览器密码管理器，账号与密码使用适当自动填充标识，不强制关闭用户已有密码管理功能。
5. 页面代码不把密码写入localStorage/sessionStorage、URL、console或报告。浏览器自己的密码保存选择不等于项目存储密码。
6. 登录请求期间禁用重复提交；发出请求后清空页面密码与显示状态，失败时重新输入，退出/重新进入也恢复隐藏。
7. 注册准备脚本的隐藏密码输入与浏览器的眼睛按钮是两件事；不为了网页方便打印初始化密码。

验收动作：输入密码→显示→隐藏→确认内容不变；按眼睛不发登录请求；键盘能切换；中文输入/粘贴正常；登录提交/失败/退出后内容清除且恢复隐藏；初始值不预置演示密码。

## 视觉与易用性验收

- 1440px桌面、768px窄屏、360px手机宽度检查；避免页面横向溢出，表格必要时局部滚动。
- 200%缩放不遮住登录、取消等关键操作；控件有可见焦点和标签，状态配文本，重要文字具备可读对比度。
- 标签、主按钮、错误、加载和空状态跨四页面一致；账号切换/失效后不能残留旧用户正文。
- 使用文本渲染政策和模型内容，不注入HTML；不以视觉美化改变权限、API或终态语义。
- 在P2先完成登录与学分页的整体预览，集中确认一次视觉方向；P3沿用已确认规则，不每页重新设计、不并行制作多套皮肤。
- 不新增UI依赖、外部字体、第三方图标网络或复杂动画。可新增局部共享布局、基础样式和SVG眼睛图标。
