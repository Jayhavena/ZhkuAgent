## 产品与设计任务

用途是实习求职展示，优先可演示、可解释、可验证。产品称“仲园 Agent / ZhkuAgent”，明确本机合成演示，不能宣称学校官方系统、真实教务接入或真实学生效果。

设计四页：登录、学分任务、本人历史与详情、重修澄清。推荐浅色校园事务工作台，课程表、结果和出处是视觉重点；可提出更好的配色和布局，但采用一个主方案，说明取舍，不无限制作方案。

主会话实现账号准备、模型验证、请求客户端、可信身份、Run/Session接线和业务验收。设计Agent通过独立HTML/CSS原型完成布局与交互，不编写新的认证实现或前端业务状态机。

## 原型数据和页面合同

固定合成示例：ART01公共选修1.5、HIS02公共选修2，合计3.5；合成政策每学期最高4学分。来源示例“合成学分规则 / synthetic-v1 / 合成第1条 / 合成本科生”，不可换成真实校园政策或声称资格确定。

登录：账号user-a/user-b/maintainer；输入密码默认空且隐藏，眼睛按钮可以反复显示/隐藏，不改值、不提交，支持键盘和可访问名称。允许粘贴/密码管理器；原型不用真实密码、不存Storage。主会话集成时负责提交/退出清空密码并复位隐藏。

学分：课程编辑、合成示例填充、提交、任务状态、取消、结果与出处。不出现没有API支持的百分比、累计统计、模型思考内容、事件实时流或费用数字。技术细节可折叠，默认用用户能理解的文案。

历史：本人列表、分页下一批与详情。API只有cursor，没有总页数；不要设计必须依赖总页数的新控件。在线Run查询与历史详情结构不同，不能把同一个字段布局视为同一个DTO。

重修：问题“选修课挂科了可以重修吗？”→追问课程类型→“专业选修课”补答；恢复的是待澄清状态，不能生成完整历史聊天。页面示意revision、有效期与取消状态，但这些值来自服务端，原型值只是示例。

## 必须设计的状态

| 区域 | 必须有的布局或示例 |
| --- | --- |
| 登录 | 默认、密码显示/隐藏、提交中、凭据错误、身份服务不可用 |
| 学分 | 未提交、已受理/运行中、请求取消但未终结、正常完成、未完成/转人工、失败、取消、超时提示 |
| 结果 | 正常答案、执行成功但正文隐藏、保存未确认且不展示正文 |
| 请求异常 | 503明确已受理并保留ID、网络确认未知且不自动重提、在线404并提供本人历史入口 |
| 历史 | 空、列表、详情、分页、正文隐藏、查不到/无权、服务不可用 |
| 重修 | 待追问、补答、重启需登录、已恢复待澄清、版本冲突、过期、取消、证据不足 |
| 通用 | 账号退出或切换后无旧用户正文、加载、窄屏、键盘焦点 |

这些是页面状态，不是都要成为独立页面。原型可用清楚标注的状态选择器集中展示，选择器属于设计预览，不能进入生产用户流程。

## 首屏预览和结束条件

先制作登录与学分主屏，交用户看一次整体方向；确认后统一补齐历史与重修及异常状态。主会话不代用户评判审美，业务事实冲突则指出具体字段。不要每个按钮都要求批准，优先一次集中修改。

检查1440px桌面、768px、360px、200%缩放；重要控件可见，必要时只有表格局部横滚。文本/状态可读、不仅靠颜色，密码按钮键盘可操作，导航和错误提示一致。

交付必须同时包含可查看原型、至少登录/学分/历史/重修四页截图或可切换视图，以及状态映射和集成说明。没有实际运行检查时明确未验证，不把截图或原型按钮当产品功能完成。
