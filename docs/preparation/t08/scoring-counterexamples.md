# T08 核验与评分反例：类别、判定分工与记录规则

日期：2026-10-14（第二轮准备）。性质：**反例类别定义与评分规则**，供正式 T08 标定“确定性校验”与“语义判断”的分工；不出新题、不预生成答案。反例合成夹具见 `tools/t08-acceptance/test/fixtures/semantic-*.json`（均显式标记 synthetic）。

## 1. 为什么需要反例标定

合同校验（字段、关系、状态）能证明“结构和身份合法”，但不能证明“主张与原文语义一致”。T05 已确立“计数和布尔字段只是声明”；同理，**字段合法不等于判断正确**。正式 T08 前必须先约定：哪些错误机器可判、哪些必须人工/模型裁判、漏拦截与误拒绝如何记录。

## 3. 确定性校验与语义判断的分工规则

1. **工具只做字段层判定**：E-SEM-* 是“记录自相矛盾”的硬错误，必须修正后才能归档；W-SEM-* 是“机器无法判定、必须人工处理”的强制提醒。
2. **语义判断必须留痕**：每条人工/模型裁判结论记录 scorer、时间、理由；模型裁判先校准，不替代事实审阅（沿用合同第 8 节）。
3. **不漏拦截也不放过工具**：
   - 反例样本必须登记 `scoring.interception`（caughtBy=tool/human/model；tool 须带 finding 码）——未登记即 E-SEM-006；
   - 工具误报（人工判定合法但工具报错）必须登记 `validatorDisposition=[{code, disposition:"FALSE_POSITIVE", reason}]`——缺理由即 E-SEM-007；
   - 两类登记用于分别统计**漏拦截**（语义错误工具没报）与**误拒绝**（工具错怪合法记录），作为工具校准依据。
4. **反例样本归组**：反例发现归 G2（已曝光）或 G4（异常注入/对抗），不得混入 G3 成功率（W-SEM-008 提示）。
5. **不用保证性措辞**：任何“已确保/必然拦截/完全覆盖”类表述禁止出现在评分记录与报告中；只能写“本次样本中工具拦截 X 条、人工拦截 Y 条、漏拦截 Z 条”。

## 4. 记录字段（T08 证据层扩展，未改合同）

| 字段 | 位置 | 用途 |
| --- | --- | --- |
| `execution.observedFacts` | `[{id, when}]` | READ 观察到的事实快照（含条件），供 CE1/CE2 机器核对 |
| `question.reference.answerPoints` | `["ap-1",...]` 或 `[{id}]` | 运行前核对的答案要点 |
| `scoring.coverageMap` | `{"ap-1":"sq-1"\|null}` | 要点→子问题映射；null=显式未覆盖 |
| `scoring.forbiddenConclusionsChecked` | boolean | CE4 人工核对声明 |
| `scoring.counterexample` | `{category:"CE1".."CE5", note}` | 本样本为反例的声明 |
| `scoring.interception` | `{caughtBy, findingCode?, note}` | 拦截方式登记 |
| `validatorDisposition` | `[{code, disposition, reason}]` | 工具误判登记 |

以上均为证据层扩展（与合同增量建议表同一性质，待用户协调后 optionally 沉淀进合同）。
