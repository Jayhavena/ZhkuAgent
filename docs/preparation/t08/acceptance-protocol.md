## 4. 操作清单

### 4.1 运行前（每组开始前）

1. 读取并确认 S1–S8 留痕；确认本组 group/category 归属（[验收矩阵](acceptance-matrix.md)）。
2. 冻结本组题目清单与参考答案；核对 `reference.verifiedBeforeRun`。
3. 确认候选 manifest；用校验工具预期参数（`--expect-source-sha` 等）记录批次头。
4. 确认环境：临时库端口、无原演示库写入、进程/容器归属本组。
5. 确认预算：次数/费用上限、单 run 上限；记录 budgetRevision。

### 4.2 运行中（每样本）

1. 每样本按 [证据记录格式](evidence-record-format.md) 落一条 T08_SAMPLE（动作/观察/结果/依据/核验/指标）。
2. 供应商失败不重试；失败尝试保留记录，usage/费用未知记 null。
3. 观察是否触发停止条件；触发即停。
4. 不修改题目、不修改参考答案、不收窄模型自由度（沿用 T05 约束）。

### 4.3 运行后（每组结束）

1. 组装 T08_BATCH；跑校验工具：`node tools/t08-acceptance/validate-evidence.mjs <batch.json> --batch --expect-group G3 ...`；ERROR 清零方可归档。
2. 按组输出统计表（五类结果、关键错误、调用/用量汇总，未知保留未知）。
3. 资源退出核对：owned 进程/容器清理、临时库状态、端口实况；缺失退出证据时该轮记未通过（沿用 reviewed-tools-01 约定）。
4. 撰写组报告：样本、输入/续答、输出、工具轨迹、供应商关联、原文、人工评分、失败案例；**只用本组数据下本组结论**。
5. 失败后处理：已曝光题归 G2 回归；一次有界修复与确认；预算耗尽留未达标。
