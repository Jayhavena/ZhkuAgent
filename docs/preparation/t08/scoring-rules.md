# T08 评分规则：维度、关键错误与结果分类

日期：2026-10-14。性质：**T08 正式验收前的准备材料**。依据主计划 T08 与 [v3 共享合同第 8 节](../design/rule-agent-contract-v3.md)，评分维度在运行前锁定，运行中不改。

## 1. 三种"完成"分离（对应主计划第 4.1 节）

| 概念 | 判定 | 说明 |
| --- | --- | --- |
| 运行完成 | 线程/资源退出，有真实结束原因 | terminated 只说明本轮资源结束 |
| 查证任务成功 | 完整回答可回答部分、说明条件及缺口、必要澄清有用 | 真实缺证的正确解释可算成功；**有依据却拒答算失败** |
| 产品目标达到 | 真实学生正确判断与原文核对质量不下降、查证耗时降低 | 属 T09，T08 不判定 |

WAITING_USER 只是阶段状态；回放未命中只是工程覆盖问题；技术失败即使表达诚实也不算成功完成可答任务。评分记录必须能区分三者，不得互相顶替。

## 2. 单题结果分类（五类，分别报告）

| 分类 | 判定 | 计数规则 |
| --- | --- | --- |
| SUCCESS 任务成功 | 可答项完整、主张有据、范围正确、缺口/澄清如实 | 计入成功 |
| TASK_FAILURE 完成失败 | 有依据但答错、漏项、答非所问、该澄清未澄清、不必要澄清、引用不相关、伪造 | 计入失败并登记原因 |
| REFUSAL 拒答 | 对正常可答题给出拒答/安全结束掩盖 | **计失败**；若参考答案判定可答而系统拒答，同时按第 4 节关键错误处理 |
| UNKNOWN 未知 | 执行环节未完成（PROCESSING_FAILURE）、缺证且无可用核验渠道 | 单列，不计成功也不计质量失败，但必须有 reasonCode 与尝试记录 |
| INDETERMINATE 不可判定 | 证据不足以外评分员判定（如轨迹缺失） | 单列；出现即该样本证据不合格，须补证或重跑 |

禁止：把 UNKNOWN 记为 SUCCESS；把 REFUSAL 记为 SUCCESS；把"安全结束"用作可答题的通过依据。

## 3. 八维度评分（每维 0/1/2，附证据来源）

| 维度 | 2 分 | 1 分 | 0 分 | 评分证据来源 |
| --- | --- | --- | --- | --- |
| D1 问题完成度 | 可答子问题全部回答，无漏项、无答非所问 | 主问题回答但有次要漏项或部分子问题未答 | 主问题未答或漏可答子问题 | 问题及补充、ResultEnvelope.items/coverage、参考答案 |
| D2 事实与条件正确性 | 主张与审核事实一致，条件/例外/操作数正确 | 次要条件或表述不精确但主结论正确 | 事实错误、条件错配、阈值判断错误 | 主张 vs factId/quote 跨度、Operation 来源 |
| D3 依据支持 | 每个主张有实际原文支持（语义层面），issue 有对应依据关系 | 依据存在但相关性弱或跨度选取不当 | 无依据确定结论、依据与主张无关 | EvidenceRelation、quote 跨度、人工语义核对 |
| D4 范围表达 | 对象/时间/用途/个人适用性限制明确，USER_DECLARED 不冒充资格 | 有限制但不完整 | 越界结论（把个人资格/现行适用性当已确认） | claims.when/conditionSource、issue.kind=SCOPE_LIMIT |
| D5 澄清必要性 | 只问必要条件、来源可溯、补充后正确续答且不重复追问 | 问了非阻塞条件或表述含混 | 该澄清未澄清（乱猜资格）、追问无关信息 | ASK 动作、conditionId、跨轮 run 链 |
| D6 引用相关性 | 展示引用均关联主张或必要澄清依据，无无关候选 | 有关联但含少量无关引用 | 无关联引用、堆砌检索候选 | EvidenceRelation、学生可见输出 |
| D7 延迟 | 达到运行前锁定的上限内且记录完整 | 超限但有一次有界说明 | 超限且无记录/掩盖 | metrics.latencyMillis、attempts |
| D8 调用与用量 | 次数/用量/费用如实记录（未知保留未知），无重复外发 | 记录不全但无重复外发 | 重复外发、未知记为 0、计数与轨迹矛盾 | metrics、供应商关联、broker 事件 |

单题维度得分只用于定位问题；**通过判定以第 4、5 节为准，不以维度均分替代**。

## 4. 关键错误（0 容忍，出现即该组失败）

1. 无依据确定规则结论或个人资格（含把背景/候选当已核验事实）。
2. 伪造引用、伪造执行成功、伪造任务状态或资源退出。
3. 资料/任务越权（跨 owner/版本读取、读取未审核资料、执行范围外工具）。
4. 把回放当在线（模式冒充、缓存复用计未预置）。
5. 重复非获准外发（重复 POST 触发重复模型调用、超授权次数/费用）。
6. **评分舞弊**：把正常可答题的拒答记为成功、删除或隐去失败样本、未知值记 0、混合四组统计。

关键错误与"诚实失败"分开登记：诚实失败（如真实缺证、明确 PROCESSING_FAILURE）单列报告，不计成功，但也不是关键错误。

## 5. 通过判据

- 全体：关键错误 0；G4 协议/权限/幂等/模式隔离检查全部通过。
- G3：逐题达到预先核对要求（运行前锁定的必要回答、禁止结论、必要条件、允许缺口）；无未解决任务完成失败。
- 重复边界任务：按题聚合全部成功比例与失败种类，**不要求工具顺序一致**；重复 run 分别记录。
- G1 全过只报回放回归通过，与其他组并列陈述。
- 达到上述各项 = "本次受控验收通过"（工程试点退出门），**不是**总体准确率承诺、不是产品上线、不是 T09 收益结论。

## 6. 评分操作规则

1. 参考答案在运行前核对并封存（问题及补充、目标范围、必要回答、禁止结论、必要条件、相关原文、允许缺口、结束要求）；**不外发、不进模型输入**。
2. 评分员不得访问未授权题集；人工评分记录 scorer、时间、每维分数、关键错误标记与理由。
3. 优先人工参考/可确定代码检查；如使用模型裁判，先校准且不替代事实审阅。
4. 开发集与新报告集分开；失败后暴露题归 G2 回归，**旧结果不回改**。
5. 失败后修复只允许一次有界修复与确认（按失败机制选择）；预算耗尽留未达标结论，不改评分标准凑通过。
