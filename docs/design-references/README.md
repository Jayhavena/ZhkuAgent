# 设计参照库

> 目的：为阶段 8 及之后的前端 UI 设计沉淀参照素材。每条笔记回答
> 「这个设计解决了什么问题、我们抄哪部分、不抄哪部分」，而不是只贴截图。
>
> 使用约束：本目录只做调研沉淀，不产生组件代码；动手重构聊天界面需等
> 阶段 8 回答卡契约冻结（见 `docs/superpowers/plans/2026-09-16-stage-8-hybrid-retrieval-agent.md`）。
> 设计令牌骨架已先行写入 `agent/frontend/src/style.css`。

## 已拍板决策（2026-09-16）

- **主题**：跟随系统明暗（`prefers-color-scheme`），不做手动切换器。
- **主色**：绿色系（呼应仲恺校色），不用纯黑白性冷淡风；
  令牌落点为 `--color-citation-accent` 及后续品牌主色变量。
- **改造范围**：首页（外壳）是纯静态页，不依赖后端契约，可随时重设计；
  对话页的卡片结构等阶段 8 契约。注意：当前首页（赛博朋克霓虹风）与
  对话页（朴素白底）风格断裂，重设计时应统一到绿色系。
- **移动端**：不做完整适配与测试；但遵守一条零成本纪律——宽度一律用
  `max-width` + flex/百分比，不写死固定像素，为以后留活口。
- **明确不做**：登录体系（违反"本机、无真实身份"约束）、多会话侧边栏
  （后端无会话列表能力，属擅自扩产品边界）、模型切换器（单链路，
  且评测前不做多模型路由）。

## 记录模板

新增参照产品时按此结构记录：

1. **解决什么问题**——该设计针对的用户痛点；
2. **关键截图**——放入本目录 `assets/`，命名 `产品-场景.png`；
3. **抄什么**——可直接借鉴的模式；
4. **不抄什么**——超出我们产品边界或当前阶段不需要的部分；
5. **对令牌的启发**——是否需要在 `style.css` 增补变量。
