# 参照：Manus —— 任务过程的分步展示（可选，阶段 8 后再评估）

## 解决什么问题

Agent 执行多步任务时，用户需要知道「做到哪一步了、这步在干什么」，
而不是面对一个长时间无反馈的加载圈。

## 抄什么

- **步骤时间线**：把 think/act 循环渲染为可折叠的步骤列表，
  每步一句话摘要 + 状态图标（进行中/完成/失败）；
- **过程与结果分离**：过程默认可折叠，最终结果始终突出——
  避免过程信息淹没答案本身。

## 不抄什么

- 终端、文件、浏览器等工具面板的实时展示——路线图明确阶段 8
  不暴露高权限工具，UI 上也不应为它们预留位置；
- 「Agent 在操作你的电脑」式的沉浸式接管感，与校园问答场景不符。

## 对令牌的启发

若做步骤时间线，可复用 `--color-feedback-subtle`（完成步骤的弱化显示）
和 `--color-degraded-warning`（失败步骤）。暂无新增变量需求。

## 备注

当前 `Agent.vue`（任务助手）的 SSE 消息是 `content + type` 的扁平流，
若阶段 8 后要把过程步骤化，需要后端消息契约先区分 step/result 类型——
UI 设计应在该契约出现后再启动，避免前后端来回返工。
