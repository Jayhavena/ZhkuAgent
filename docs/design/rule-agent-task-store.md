# T04：短期任务、续答和幂等

2026-10-13。实现为RuleAgentTaskStore，依赖T01合同、T02证据工具和T03循环。本项仅内部工程链路，尚未连接HTTP或学生页面。

## 可观察行为

创建时按可信Owner（actorId与sessionNonce）和客户端请求UUID占位，再交给宿主执行器。相同owner/动作/键及载荷返回同一task、turn、run；同键异载荷冲突。响应未知时查询请求键，不换键重复执行。

每次必要澄清结束当前run。补充时校验归属、版本、继续token和有效期，在锁外重验此前实际证据，再回锁核对版本并创建同task的新turn/run。两个窗口不能同时消费同一版本。已确认条件保留，改变问题目标或不明确的补充拒绝直接合并。

模型与证据读取在短锁外执行。活动run的取消先申请runtime停止；只有实际运行退出并生成终止快照后才能显示STOPPED。迟到内容不得覆盖取消。宿主拥有执行器，Store关闭不擅自关闭共享线程池。

调度拒绝或工作异常发布TASK_EXECUTION_UNAVAILABLE（PROCESSING_FAILURE），不能解释为资料没有规定。Java与前端原因码同步；真实Java调度失败快照另经前端消费校验。

## 容量与保留边界

默认最多128个task、每actor跨Session合计8个task、512个请求键。task保留15分钟、必要澄清token有效5分钟；每task最多3个run、12次模型尝试、2轮必要澄清。均为防御上限，不是性能承诺。历史仅保留各轮消息、条件、状态及尝试次数，不是长期咨询档案。

请求索引满时，已有同键同载荷重试仍返回原受理身份；只有新请求受到容量限制，检查须早于task创建、nonce消费或取消状态改变。活动任务过期仍占容量至实际退出，不能靠清理索引隐藏未退出的工作。

重启不恢复内存；未知/过期表示当前无法确认受理历史，不表示从未调用。当前cancel接口仅作用于活动run；WAITING_USER已无工作线程，界面结束等待及新任务动作在T06/T07结合合同处理，不伪造取消旧run。

自然补充目前接受审核allowedValues，以及courseType的少量完整明确表达。其他补充返回NEEDS_CONFIRMATION；这不能证明开放自然语言理解，T05/T08仍须验证未预置表达。子问题仅按明确分号保留原句，不声称语义拆分已完成。ACTIVE快照中的执行计数为未发布占位，最终计数只在终止快照确认；T05/T06若展示实时用量，必须接入实际计数而不能把占位0解释成尚未调用。
